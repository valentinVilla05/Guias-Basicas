# 2.1 Gestión de Procesos
## 2.1.1 Definiciones
* **Proceso**: Es un **programa en ejecución**. A diferencia de un programa (que es un archivo *estático* en un disco con código de instrucciones), un proceso es una entidad activa que evoluciona con el tiempo y consume recursos del sistema

* **Recursos del Proceso**: Eelemtnsodel hardware y del sistema operativo que un proceso necesita para ejecutarse. Incluye:
    * **Tiempo de CPU**: Ciclos del procesador necesarios para ejecutar las instrucciones
    * **Memoria Principal (RAM)**: Espacio donde se almacena el código , los datos y la pila (stack)
    * **Ficheros y Dispositivos E/S**: Archivos abiertos, puertos de red, teclado, pantalla.....
* **Ejecución Concurrente**: Situación en el que varios procesos se encuentran en desarrollo simultáneamene (progresando al mismo tiempo en el sistema)

## 2.1.2 Paradigmas de Ejecución en el Sistema Operativo
* **Multiprogramación**: Técnica que permite al sistema operativo albergar varios procesos en memoria y **entremezclar su ejecución** en el sistema
    * **Objetivo Principal**: Maximzar el rendimiento y la **utilización de los recursos** del ordenador 
* **Tiempo compartido (Time-Sharing)**: Extensión de multiprogramación dodne la CPU alterna entre múltiples procesos tan rápidamente que dan la sensación de que todos los programas se ejecutan simultaneamente
    * **Objetivo Principal**: Proporcionar un **tiempo de respuesta razonable** e interactivo al usuario

## 2.1.3 Funciones del Sistema Operativo en la Gestión de Procesos
Para abstraer y manejar los procesos el sistema operativo debe realizar 4 tareas clave:

1. **Asignación de Recursos**: Garantiza que cada proceso reciba de forma aislada y segura la memoria, archivos y periféricos que requiere
2. **Planificación (Scheduling)**: Selecciona que proceso se ejecuta en la CPU en cada momento y durante cuanto tiempo , siguiendo **políticas específicas**
3. **Prevención y Control de Interbloqueos (Deadlocks)**: Mecanismos para evitar que dos o más procesos queden bloqueados indefinidamente esperando recursos q se están reteniendo
4. **Sincronización y Comunicación entre procesos (IPC)** Se usan herramientas como semáforos que permiten a los procesos coordinar sus acciones e intercambiar datos sin interferir entre sí

## 2.1.4. Las Dos Dimensiones del Proceso y la Introducción a Threads
El concepto tradicional de proceso combina dos características  **independientes**:
| Dimensión | Definición | Función | 
| -- | -- | -- |
| **1. Unidad de Asignación y Propiedad de Recursos** | El proceso es el "contendor" al que el sistema operativo asigna el espacio de dirección de memoria, archivos y dispositivos | Garantiza la protección y el aislamiento de programas |
| **2. Unidad Planificable** | Es el hilo de ejecución individual que el planificador del sistema operativo asigna a la CPU para ejecutarse | Es la entidad sobre las que se mide el tiempo de procesamiento |
|

* **Origen de los Hilos o Threads**: Al separar estas dos características surge el concepto de **hilo** que es la unidad planiifcable dentro del proceso. Un solo proceso puede tener muchos hilos que comparten la misma memoria pero se ejecutan de forma independiente

## 2.1.5 Programa vs Proceso
| Criterio | Programa | Proceso | 
| -- | -- | -- |
| **naturaleza** | Concepto **estático** (secuencia de instrucciones estrica en un archivo/disco) | Concepto **dinámico** (instancia de ejecución de ese programa en memoria) |
| **Entidad** | Pasiva | Activa(evoluciona en el tiempo) |
| **Relación N a 1** | Un único programa puede ser ejecutado por varios usuarios a la vez | cada ejecución genera un **proceso independiente** con su propio contexto |
| **Contexto** | Solo código fuente o binario | Posee **CPU**, **Registros**, **contador de programa (PC)**, **pila(stack)**, **datos** y **segmento de texto** | 

## 2.1.6 El modelo de Procesos y el Procesador Virtual
Para simplifiar el control de la máquina , el Sistema Operativo organiza toda la ejecuciób bajo un modelo estandar:
* **Estructuración**: Todos los programas en ejecución (tanto apps del  usuario como los propios servicios del SO) se organizan como un conjunto de procesos
* **Procesador Virtual**: cada proceso tiene su propia **CPU** de dedicada
* **Realidad de Hardware**: La CPU real conmuta (muta de un proceso a otro a gran velocidad), repitiendo su tiempo entre todos los procesos acivos mediante la **multiprogramación**

## 2.1.7 Implicaciones y Comportamiento de la Ejecución Concurrente
Debido a que la CPU cambia constantemente entre procesos, la ejecución presenta propiedades clave que deben tenerse en cuenta:
1. **Velociad de ejecución no uniforme**: La rapidez a la que avanza un proceso depende directamente del número de procesos en el sistema y del timepo de CPU que se le asigne
2. **No reproducibilidad de tiempos**: Dos ejecuciones sucesivas del mismo programa o tardarán exactamente lo mismo. NO se puede hacer suposiciones sobre el tiempo de ejecución
3. **Pérdida de determinismo temporal**: Un bucle de espera de un proceso no garantiza intervalos reales fijos ya que la CPU puede ser qiutada a la mitad de bucle pa antender a otros procesos

## 2.1.8 Los 3 Estados Básicos de un Proceso
Durante su ciclo de vida se encuentra en uno de estos 3 estados:

| Estado | Definición | Requisitos/Condición |
| -- | -- | -- |
| **Ejecución (Running)** | El proceso está ocupando la CPU y ejecutando sus instrucciones en el instante actual | Posee **todos** los recursos , includida la CPU | 
| **Listo o Preparado (Ready)**: | El proceso se encuentra a la espera de que el sistema Operativo le asigne el uso de la CPU | Posee **todos** los recursos necesarios **Excepto la CPU** | 
| **Bloqueado (blocked)** | El proceso está detenido a la espera de que se produzca un evento externo (ej : lecura de disco) | Le falta la CPU y **algún otro recurso o evento externos**

## 2.1.9 Transiciones entre estados
```text
            ┌──────────────────────────────────────────────┐
            │                                              │
            ▼                                              │
     ┌──────────────┐         (1) Despacho          ┌──────────────┐
     │              ├──────────────────────────────►│              │
     │    LISTO     │                               │  EJECUCIÓN   │
     │              │◄──────────────────────────────┤              │
     └──────────────┘      (2) Tiempo expira        └──────┬───────┘
            ▲                                              │
            │                                              │ (3) Espera por
            │               ┌──────────────┐               │     un evento
            │               │              │               │
            └───────────────┤  BLOQUEADO   │◄──────────────┘
             (4) Ocurre el  │              │
                 evento     └──────────────┘
```
**Listo ──► Ejecución** (Despacho / Dispatch): El planificador (scheduler) selecciona este proceso de la lista de listos para asignarle la CPU.

**Ejecución ──► Listo** (Expropiación / Preemption): Se le agota el cuanto de tiempo de CPU asignado o se presenta un proceso de mayor prioridad.

**Ejecución ──► Bloqueado** (Espera de evento): El proceso solicita una operación de Entrada/Salida o necesita un recurso no disponible de forma inmediata.

**Bloqueado ──► Listo** (Desbloqueo / Ocurrencia de evento): Ocurre el evento externo esperado (p. ej., termina la lectura de un archivo); el proceso pasa a estar disponible para competir de nuevo por la CPU.

> Un proceso **NUNCA** pasa directamente de Bloqueado a Ejecución. Siempre debe pasar primero por el estado de Listo para que el planificador organice su acceso al procesador.

## 2.1.10 Estructuras de Organización: Colas y Listas de Procesos
Dado que puede haber múltiples procesos en estado de Listo y Bloqueado, el Sistema Operativo utiliza listas/colas de gestión:

### A. Lista de Procesos Listos (Ready Queue)
* **Cantidad**: Existe únicamente UNA lista de procesos listos en todo el sistema.

* **Organización**: Se encuentra ordenada según criterios de prioridad o la política de planificación aplicada.

* **Funcionamiento**: El primer proceso de esta lista será siempre el siguiente en recibir la CPU.

B. Listas de Procesos Bloqueados (Blocked Queues)

* **Cantidad**: Suelen existir **MÚLTIPLES** listas, organizadas típicamente una por cada tipo de evento o recurso esperado (ej. Cola de espera para Disco, Cola de espera para Teclado, Cola para Red).

* **Organización**: Por lo general **NO** están ordenadas por prioridad de CPU, sino que se procesan a medida que ocurren los eventos (asíncronamente).

* **Excepción:** Si múltiples procesos se bloquean esperando el mismo evento exacto, se les pueden asignar prioridades dentro de esa cola específica para decidir cuál se desbloquea primero.

## 2.1.11. Ejemplos de Transiciones y Causante del Cambio
Cada transición de estado está provocada por eventos específicos del sistema
| Transición | Eventos Desencadenantes |
| --- | --- |
| Ejecución ──► Bloqueado | • Iniciar una operación de Entrada/Salida (E/S). • Ejecutar una operación WAIT sobre un semáforo a cero. • Solicitar un recurso no compartible asignado a otro proceso. | 
| Ejecución ──► Listo | • Agotar el tiempo asignado (cuanto) en un sistema de tiempo compartido. • Expropiación de la CPU decidida por el Sistema Operativo. | 
| Listo ──► Ejecución | • Selección por parte del Planificador de la CPU (Scheduler). |
| Bloqueado ──► Listo | • Finalizar la operación de E/S solicitada. • Ejecutar una operación SIGNAL sobre el semáforo en que se bloqueó.| 
|

> De las 4 transiciones, el bloqueo es la única iniciada por el propio proceso de usuario (de forma indirecta mediante una llamada al sistema o system call). Las otras 3 transiciones las inician entidades externas (el SO, interrupciones de hardware o eventos de otros procesos)

## 2.1.12. Descripción y Manifestación Física de un Proceso: La Imagen del Proceso

La Imagen del Proceso es el conjunto de elementos que componen la presencia física y lógica de un proceso en la memoria del ordenador:
$$\text{Imagen del Proceso} = \text{Código} + \text{Datos} + \text{Pila} + \text{PCB}$$

1. **Código (Segmento de Texto / Programa):** Conjunto de instrucciones que van a ser ejecutadas por la CPU.

2. **Datos:** Espacio destinado a las variables locales, globales y constantes definidas por el programa.

3. **Pila (Stack):** Estructura de memoria usada para gestionar el flujo del programa (llamadas a procedimientos/funciones, direcciones de retorno y paso de parámetros).

4. **Bloque de Control de Proceso (PCB - Process Control Block):**

    * **Definición:** Estructura de datos interna del Sistema Operativo que almacena los atributos de control y estado del proceso

    * **Función:** Es la manifestación misma del proceso ante el sistema operativo; permite suspender su ejecución y reanudarla más tarde exactamente en el mismo punto.

## 2.1.13 El Bloque de Control de Proceso (PCB)
El **Bloque de Control de Proceso (PCB)** es la estructura de datos central y más importante del sistema operativo. Contiene toda la información necesaria para el control y la administración de un proceso individual.

* **Estado del Sistema:** El conjunto de todos los PCB define el estado global del sistema operativo.


* **Ubicación:** Todos los PCB se almacenan en memoria principal dentro de la Tabla de Procesos (implementada como vector o lista enlazada) para garantizar una consulta rápida.


* **Soporte Hardware:** Dado su uso intensivo, los procesadores suelen incluir un registro hardware que apunta directamente al PCB del proceso en ejecución.

## 2.1.14 Operaciones con Procesos
Un sistema operativo multiprogramado debe gestionar el ciclo de vida completo de cada proceso mediante las siguientes operaciones:

### A. Creación de un Proceso
Instanciar un nuevo proceso implica realizar los siguientes pasos de forma secuencial:

1. **Asignar ID único:** Se otorga un identificador (PID) no utilizado al nuevo proceso.

2. **Insertar en la Tabla de Procesos**: Se reserva una nueva entrada en la tabla primaria del sistema.

3. **Asignar Espacio en Memoria:** Se reserva memoria para el espacio de direcciones privado (código, datos y pila de usuario) y para el propio PCB

4. **Inicializar el PCB:**
    * **IDs**: Se configuran PID, PPID y UID

    * **Registros:** Se inicializa el Contador de Programa (PC) con el punto de entrada del programa y los punteros de pila.

    * **Control:*** Se establece el estado inicial (normalmente Listo) y la prioridad (por defecto o solicitada)

5. **Asignar Recursos Iniciales:** Entradas/salidas por defecto (p. ej., `stdin` y `stdout`).

6. **Establecer Enlaces/Punteros:** Se inserta el proceso en la cola correspondiente (p. ej., Lista de Listos)

7. **Estructuras Auxiliares:** Se crean registros administrativos (facturación, monitorización de rendimiento)

8. **Relación Jerárquica (Padre/Hijo):** La creación de un proceso por parte de otro origina un árbol jerárquico. Cada proceso hijo tiene un único padre, aunque un padre puede tener múltiples hijos.

```text
                 [ Proceso Padre ]
                          │
                  ┌───────┴───────┐
                  ▼               ▼
             [ Hijo 1 ]       [ Hijo 2 ]
```

Mecanismo de Creación en UNIX: `fork()`, `exec()` y `wait()`

* `fork()` : Crea un prceso hijo mediante la duplicación exacta de la imagen del padre (código, datos, pila y PCB). Ambos continuan en la instruccion posteior a `fork()``pero con un valor de retorno diferente
    * Al hijo le devuelve `0`
    * Al **padre** le devuelve el **PID del hijo** (valor > 0)
* `exec()`: Usada por el hijo tras el `fork()`. Remplaza el espacio de direcciones actual cargando un nuevo archivo ejecutable
* `wait()`: Ejecutada por el padre si desea bloquearse hasta que el proceso hijo finalice su ejecución

### B. Destrucción o Eliminación de un Proceso
Destruir un proceso consiste en purgar su presencia en el sistema operativo:

1. Se elimina de las listas y tablas del sistema (Tabla de procesos, Lista de listos/bloqueados).

2. Se liberan y devuelven al sistema todos los recursos asignados (memoria, ficheros abiertos, dispositivos E/S).

3. Se destruye y libera el espacio ocupado por su PCB.

> **Gestión de Descendientes:** Según el sistema operativo, al destruir un proceso padre, sus hijos pueden eliminarse automáticamente en cascada o permanecer como procesos independientes.

### C. Suspensión y Reanudación de un Proceso
* **Suspensión (Paso al Estado Suspendido):** Consiste en desalojar la imagen del proceso de la memoria principal y transferirla al disco (intercambio / swapping).

    * **Motivo principal:** Liberar memoria RAM y mitigar sobrecargas en momentos de alta demanda.

    * **Gestión de Recursos:** La memoria se libera de forma inmediata; los archivos y dispositivos se retienen brevemente, pero se liberan si la suspensión se prolonga.

* **Reanudación:** Devuelve el proceso a memoria principal y lo restituye al estado previo para que continúe desde el punto exacto donde se detuvo.

### D. Otras Operaciones Básicas
**Cambiar la prioridad:** Modificación del campo de prioridad almacenado en el PCB.

**Bloquear / Desbloquear:** Transiciones asociadas a la espera o recepción de eventos (E/S, semáforos).

* **Planificar:** Selección y asignación de la CPU por parte del scheduler.

* **Comunicación entre procesos (IPC)**: Intercambio de mensajes o memoria compartida entre tareas.

## 2.1.15 Suspensión y Reanudación de Procesos
La operación de **suspensión** implica el desalojo de la memoria RAM del a imagen del proceso y su transferencia al almacenamiento secundario. La reanudación reactiva el proceso cargándolo nuevamente en memoria

### Razones para la Suspensión
1. **Intercambio (Swapping) / Reducción de Carga Máxima**: Liberar RAM para dar cabida a procesos de alta prioridad o reducir la saturación de memoria
2. **Fallos del Sistema**: Suspender rpcesos para corregir fallos del sistema o aislar un proceso sospechoso sin perder su estado
3. **Solicitud de Usuario Iterativo**: depuración de código o pausa manual de tareas
4. **Temporización**: procesos periódicos que permanecen suspendidos hasta el siguiente intervalo
5. **Solicitud del Proceso Padre**. Coordinar o examinar la  actividad de sus descencientes

### Modelo de Estados con Suspensión (Modelo de 5/7 Estados)
Para soportar el **swapping** introducen dos nuevos estados sobre el modelo básico , creando una separación entre **Estados Activos (en memoria RAM) y estados suspendidos (en disco)**

### Descripción de los Estados Suspendidos
* **Suspendido / Listo (Ready Suspended)**: El proceso está en disco, pero **posee todas las condiciones para ejecutarse** salvo disponer de memoria RAM y CPU
* **Suspendido / Bloqueado (Blocked Suspended)**: El proceso está en disco y **sigue esperando que curra un evento** externo (E/S, semáforo, etc)

### Transiciones Clave entre Estados Suspendidos y Activos
**Bloqueado** ──► **Suspendido-Bloqueado:** El SO decide liberar la RAM que ocupa un proceso bloqueado pasándolo a disco.

**Suspendido-Bloqueado** ──► **Suspendido-Listo:** Ocurre el evento esperado mientras el proceso sigue en disco. No pasa a memoria inmediatamente, sino que espera a ser reanudado.

**Suspendido-Listo** ──► **Listo:** El SO vuelve a cargar la imagen del proceso desde disco a memoria principal cuando hay espacio disponible.

> **Regla de Prioridad:** La suspensión es una operación de alta prioridad gestionada de inmediato por el Sistema Operativo para optimizar recursos.

## Control de Prcesos
### Modos de Ejecución del Procesador
Para proteger la integridad del sistema y aislar los datos críticos del Sistema Operativo de posibles errores de los programas de usuario, el procesador soporta al menos **dos modos de ejecución**

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                           MODO USUARIO                                 │
 │ • Menor privilegio.                                                    │
 │ • Ejecución restringida (sin acceso directo a hardware o RAM del SO).  │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    │ Interrupción / Llamada al Sistema
                                    ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │                     MODO NÚCLEO / SUPERVISOR                           │
 │ • Mayor privilegio (control total del procesador).                     │
 │ • Ejecuta instrucciones privilegiadas (E/S, PSW, gestión de memoria).  │
 └────────────────────────────────────────────────────────────────────────┘
```

### Comparativa de Modos
| Características | Modo Usuario (User Mode) | Modo Núcleo / Supervisor (kernel Mode) |
| -- | -- | -- | 
| **Nivel de Privilegio** | Restringido / Bajo | Total / Máximo | 
| **Instrucciones permitidas** | Solo instrucciones no privilegiadas (cálculo o lógica) | **Todas** incluidas instrucciones privilegiadas (E/S, modificaciópn de memoria, control de interrupciones..)
| **Acceso a memoria** | Solo al espacio de memoria asignado al proceso | Acceso completo a toda la memoria del sistema y estructuras del SO | 
|

 ### Control y Cambio de Modo Hardware
 1. **Identificación de Modo** El procesador conoce en qué modo se está ejecutando gracias a un **bit de modo** ubicado en el registro de estado o **Palabra de Estado del Programa (PSW - Program Status Word)**
 2. **Cambio de Modo**:
    * **Modo Usuario -> Modo Núcleo**: Ocurre automáticamente cuando se genera una llamada al sistema (system call), una interrupción de hardware o una excepción. El bit de la PSW cambai para permitir la ejecución del código del Sistema Operativo
    * **Modo Núcleo -> Modo Usuario**: El SO restablece el bit de la PSW antes de devolver el control al programa de usuario

### A. Tratamiento de Interrupciones y Cambio de Contexto
Cuando ocurre una interrupción de hardware, excepción o llamada al sistema (system call), el procesador debe intervenir inmediatamente:
1. **Salvar el Contexto**: Se guarda info de estado del procesador (contador de programa / PC, registros del proceasdor y punteros a la pila) en la pila del sistema o en el PCB
2. **Transferir el control al SO**: Se carfa en el PC la dirección de incio de la **rutina de tratamiento de la interrupción**
3. **Ejecución del Tratamiento**: Es una rutina corta en modo núcleo que realiza tareas básicas (marcar indicaciones , enviar acuses de recibo a dispositivos de E/S)...

> **Definición de Cambio de Contexto:** Es la salvaguarda y posterior restauración del estado del procesador para permitir la ejecución de una rutina del sistema sin cambiar el estado del proceso de usuario en ejecución.

* Coste: Muy bajo (se realiza en gran medida por hardware).

### B. El Cambio de Proceso (Conmutación de Proceso)
Ocurre cuando la interrupción o suceso determina que el proceso actual no debe continuar en la CPU, haciendo necesario asignar el procesador a un nuevo proceso

> Regla Clave: Un cambio de proceso implica obligatoriamente al menos dos cambios de contexto, pero exige además una reestructuración profunda en las tablas del Sistema Operativo.

* Coste: Elevado (requiere intervención pesada por software del SO)

### C. Pasos Involucrados en un Cambio Completo de Proceso
Cuando se determina que un nuevo proceso ocupará la CPU, el Sistema Operativo realiza los siguientes 7 pasos secuenciales:
| Pasos | Acción | Descripción | 
| -- | -- | -- |
| 1 | **Salvar el contexto** | Guardar el PC, registros y punteros de pila del proceso saliente | 
| 2 | **Actualizar el PCB del proceso saliente** | Cambiar su estado (a Listo, Bloqueado o Suspendido) y actualizar campos de contabilidad/motivo de salida | 
| 3 | **Mover el PCB a la cola correspondiente** | Insertar el PCB en la lista adecuada (Cola de Listos, Cola de Bloqueados por evento i, etc.) |
| 4 | **Seleccionar otro proceso** | El planificador (scheduler) elige el siguiente proceso a ejecutar según la política del sistema | 
|  5 | **Actualizar el PCB del nuevo proceso** | Cambiar su estado a **En Ejecución**
| 6 | **Actualizar la Gestión de Memoria** | Reconfigurar las estructuras de traducción de direcciones (tablas de páginas o segmentos) para el nuevo proceso |
| 7 | **Restaurar el Contexto** | Cargar los registros y el PC con los valores almacenados previamente en el PCB del nuevo proceso para reanudar su ejecución | 

### D. Tabla Comparativa Resumen 
| Características | Cambio de Contexto | Cambio de Proceso | 
| -- | -- | -- | 
| **¿Modifica el estado del proceso?** | **NO**, sigue en ejecución | **SI** (pasa a listo, bloqueado, etc) | 
| **Entidades involucradas** | Proceso actual -> Rutina del SO -> Proceso Actual | Proceso A -> Planificador del SO -> Proceso B | 
| **Actualización de PCB/Memoria** | No altera el PCB ni la memoria del usuario | Modifica PCBs, colas de estado y tablas de memoria |
| **Sobrecarga de trabajo** | Mínima | Alta |
