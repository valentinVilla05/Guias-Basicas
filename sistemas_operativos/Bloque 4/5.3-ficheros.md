# 5.3 Sistemas de Ficheros
## 5.3.1 Introducciónb al Sistema de Ficheros
El **Sistema de Ficheros** es el módulo dele sistema operativo encargado de la administración y manipulación del almacenamiento secundario. Oculta la complejidad física de los dispositivos de almacenamiento ,foreciendo una interfaz abstracta y transparente para los usuarios y programas

```text
SISTEMA DE FICHEROS
 ├── 1. Colección de Ficheros ──► Almacenan los datos del usuario/sistema.
 └── 2. Estructura de Directorios ──► Organizan y proporcionan metadatos.
```

### Justificación del Almacenamiento Persistente
Las aplicaciones no pueden almacenar sus datos exclusivamente en el espacio de direcciones de un proceso debido a 3 limitaciones:
1. **Capacidad Limitada**: SRestringida por la memoria princiap y el espacio de direcciones virtuales
2. **Volatilidad**: Si el proceso o el sistema termina, la información en memoria se pierde
3. **Falta de concurrencia**: La información en el espacio de direcciones de un proceso no es accesible de forma simultánea por otros procesos

Un **fichero** es una abstracción persistente (independiente de la vida de los procesos) representada por una secuencia de bytes, lineas o registros cuya interpretación corresponde a la aplicación que lo utiliza

## 5.3.2 Perspectiva del Usuario (Visión Lógica)
Desde el punto de vista del usuario, el sistema de ficheros se define por cómo se nombran, clasifica, estructuran, operan y mapean los ficheros

### 1. Nombres y escritura
*   **Nombre**: Identifcan de manera única los ficheros. Se suele dividir en **nombre base** y **extensión** ej: archivo.txt
* **Formato de Texto**: Antes usaban ASCII. En sistema modernos como linux la codificación estándar es **UFT-8**, la cual mantiene compatibilidad hacia atrás con los primeros 128 caracteres ASCII
* **Binarios**: Ficheros no imprimibles con formatos internos específicos definidos por las aplicaciones

### 2. Tipos de Ficheros en sistemas POSIX/UNIX
```text
TIPOS DE FICHEROS EN UNIX
 ├── Regular/Ordinario ( - )  ──► Datos ASCII, UTF-8 o Binarios introducidos por usuarios/aplicaciones.
 ├── Directorio        ( d )  ──► Contiene una lista estructurada de nombres de otros ficheros.
 ├── Enlace Simbólico  ( l )  ──► Referencia textual (ruta) a la ubicación de otro fichero.
 ├── Dispositivo Esp.  ( c/b )──► Interfaz para periféricos de Carácter (teclado) o Bloque (disco).
 └── Tubo con Nombre   ( p )  ──► Named Pipes para comunicación IPC entre procesos.
```

* Ejemplso en consola (`ls -l`):
* **Regular:** `-rw-r--r-- ... /etc/passwd`

* **Directorio:** `drwxr-xr-x ... /`

* **Enlace simbólico:** `lrwxrwxrwx ... termcap -> /usr/share/misc/termcap`

* **Dispositivo de carácter:** `crw------- ... /dev/null`

* **Dispositivo de bloque:** `brw-rw---- ... /dev/sda`

* **Tubo con nombre:** `prw-rw---- ... mypipe`

### 3. Atributos de los Ficheros (Metadatos)
Además de los datos puros, el sistema operativo asocia un conjunt ode atributos a cada fichero

* **Identificación y Propiedad**: Nombre, propietario (UID), grupo (GID)
* **Protección y Control**: Premisos de lectura, escritura y ejecucción
* **Temporalidad**: Fecha/hora de creación, último acceso y última modificación
* **Tamaño y Ubicación**_ Tamaño actual y dirección física/lógica de los bloques

### 4. Operaciones Básicas sobre Ficheros
Las llamadas al sistema (system calls) más comunes que la interfaz ofrece a los programas son:

| Llamada al Sistema | Descripción |
| :--- | :--- |
| **CREATE** | Crea la entrada en el directorio y asigna la estructura inicial. |
| **DELETE** | Elimina la referencia en el directorio y libera los bloques asociados. |
| **OPEN** | Conecta el fichero al espacio de direcciones del proceso y retorna un descriptor. |
| **CLOSE** | Desconecta el fichero y libera los buffers en memoria. |
| **READ / WRITE** | Transfiere datos desde/hacia la posición indicada por el puntero de acceso. |
| **APPEND** | Añade datos siempre al final del fichero. |
| **SEEK** | Reposiciona el puntero de lectura/escritura (acceso aleatorio). |
| 

### 5. Ficheros Mapeados en Memoria
Mapear un fichero en memoria consiste en asociar el contenido del archivo directamente a una región del espacio de direcciones virtuales del proceso (a través de llamadas estilo MAP / UNMAP o `mmap` en UNIX)

```text
ESPACIO DE DIRECCIONES VIRTUAL                      DISCO (FICHERO)
┌────────────────────────────────┐                 ┌───────────────┐
│           Código               │                 │               │
├────────────────────────────────┤                 │   Fichero en  │
│ Fichero Mapeado en RAM (mmap)  │ ◄──────────────►│    Disco      │
├────────────────────────────────┤                 │               │
│            Pila                │                 └───────────────┘
└────────────────────────────────┘
```

#### Ventajas:
* **Rendimiento:** Evita el uso repetido de buffers intermedios y llamadas `READ`/`WRITE`
* **Simplicidad:** El archivo se trata como si fuera una estructura de datos en RAM (un array o puntero)

#### Inconvenientes
* **Sincronización y Modificación:** Riesgo de inconsistencia si múltiples procesos acceden y modifican el archivo simultáneamente sin cerrojos

* **Gestión del Tamaño:** Dificultad para ajustar dinámicamente la longitud del archivo si este crece

* **Restricción de Espacio:** Archivos muy grandes pueden no caber en el espacio de direcciones virtuales del proceso, obligando a mapear el archivo por fragmentos

#### Organización Lógica de los Datos
Existen tres paradigmas para estructurar los datos dentro de un fichero:

1. **Secuencia no estructurada de bytes**: El sistema operativo no interpreta el contenido del fichero. La semántica y la estructura las imponen los programas de usuario. Proporcionan máxima flexibilidad (Enfoque de UNIX y Windows)

2. **Secuencia de registros de longitud fija**: Ficheros estructurados en unidades de lectura / escritura de tamaño constante

3. **Árbol de registros (ISAM - Index Sequential Access Method)**: Registros de longitud variable ordenados mediante una clave fija para optimizar búsquedas. Utilizado en entornos mainframe

#### Métodos de Acceso

* **Secuencial:** Los datos se leen o escriben de principio a fin de forma ordenada. Típico de soportes como cintas magnéticas

* **Aleatorio / Directo**: Se puede leer o escribir en cualquier posición del fichero de forma inmediata (acceso por posición/byte usando `Seek`. Propio de discos interactivos)


### 6, Estructura de Directorios
Los directorios son ficheros especiales que contienen entradas para localizar otros ficheros en almacenamiento

#### Evolución de la Organización
```text
A) Directorio Único (Primitivo)     B) Directorio por Usuario         C) Estructura Jerárquica (Árbol)
┌──────────────────────────────┐     ┌──────────────────────────┐      ┌──────────────────────────────┐
│  /  [F1] [F2] [F3] [F4]      │     │  / ──► UserA [F1, F2]    │      │  / (Raíz)                    │
│  (Conflictos de nombres)     │     │    └──► UserB [F1, F3]   │     │  ├── bin/                    │
└──────────────────────────────┘     └──────────────────────────┘      │  └── home/ user1/ docs/      │
                                                                       └──────────────────────────────┘
```

#### Rutas de Acceso
* **Ruta ABsoluta**: Comienza siempre en el directorio raíz (`/` en UNIX o `C:\` en Windows)

* **Ruta relativa**: Se evalúa a aprtir del directorio de **trabajo actual** ( current working directory)

#### Operaciones Básicas sobre Directorios
* `CREATE` / `DELETE`: Crea o elimina un directorio.

* `OPENDIR` / `CLOSEDIR`: Abre o libera un descriptor de directorio.

* `READDIR:` Lee secuencialmente las entradas de un directorio.

* `RENAME:` Renombra la entrada de directorio

* `LINK` / `UNLINK:` Crea o elimina enlaces entre directorios/ficheros

### 7. Perspectiva del Sistema Operativo
Casi todos los sistemas de ficheros dividen los datos en **bloques de tamaño fijo** (potencias de 2 que agrupan varios sectores del disco) para evitar tener que reubicar ficheros contiguos cuando crecen


```text
Utilización del Espacio (baja fragmentación)
     ▲
100% │ \
     │  \     ZONA DE COMPROMISO
     │   \    (512B - 4KB)
     │    \ ┌──────────┐
     │     │          │ \
  0% └─────┴──────────┴──┴──────────────────► Tamaño de Bloque
  0% ┌───────────────────┬──────────────────┐ 100%
     │                   │                  │
     ▼                   ▼                  ▼
Velocidad b/s (baja)   Ideal            Velocidad (alta)
(Muchas búsquedas)                    (Alta frag. interna)
```

#### 1. Bloques Muy grandes (ej. Cilindros/32 KB)
* **Ventaja:** Alta velocidad de transferencia (menos búsquedas de disco)

* **Desventaja:** Gran desperdicio de espacio por fragmentación interna (ficheros pequeños ocupan un bloque completo)

#### 2. Bloques Muy Pequeños (ej. 512 Bytes):
* **Ventaja:** Excelente aprovechamiento del espacio en disco

* **Desventaja:** Velocidad de transferencia muy lenta (cada fragmento exige posicionar el cabezal del disco mediante operaciones de búsqueda y latencia)

> **Estándar actual:** Se suelen elegir bloques de 1 KB, 2 KB o 4 KB. En sistemas Linux modernos con Ext4, el tamaño por defecto suele ser de 4096 bytes (4 KB)

#### Verificación del Tamaño de Bloque en Linux
```bash
# 1. Identificar el punto de montaje del sistema de ficheros
df -h

# 2. Consultar la información del sistema de ficheros (Block size)
stat -f /
```

### 8. Estructura Interna de los Directorios
Un directorio es un fichero especial cuya función principal es mapear el **nombre lógico de un fichero con su información física** en el dispositivo de almacenamiento. Cada entrada del directorio almacena un Bloque de Control del Fichero (FCB) o una referencia al mismo

**Comparativa: Entradas de Directorio en DOS vs. UNIX**

| Característica | MS-DOT (FAT) | UNIX (POSIX) | 
| -- | -- | -- | 
| **Tamaño de entrada** | 32 bytes | 16 bytes (en estructuras clásicas) | 
| **Contenido de la entrada** | Nombre + Extensión (11 B), atributos, hora/fecha, tamaño y **puntero al 1.º bloque** | **Nombre del fichero** (14 B) + **Número de nodo-i** (2 B) | 
| **Ubicación de metadatos** | Dispersos en la propia entrada del directorio y en la tabla FAT | Centralizada exclusivamente en el **nodo-i** (i-node) |
|

```text
ENTRADA DE DIRECTORIO EN DOS (32 Bytes):
┌─────────────────┬───────────┬───────┬───────────┬──────────────┐
│ Nombre/Ext (11B)│ Atrib (1B)│ ...   │ Tamaño(4B)│ 1º Bloque(2B)│ ──► Apunta al 1.º bloque en disco.
└─────────────────┴───────────┴───────┴───────────┴──────────────┘

ENTRADA DE DIRECTORIO EN UNIX (16 Bytes):
┌───────────────────────────┬───────────────┐
│  Nombre del Fichero (14B) │  Nodo-i (2B)  │ ──► Apunta a la tabla de nodos-i.
└───────────────────────────┴───────────────┘
```

#### Búsqueda y Resolución de Ruta (Ejemplo: `/usr/ast/mbox`)
Para resolver una ruta absoluta, el kernel parte siempre del directorio raíz (`/`), cuyo nodo-i se encuentra en una ubicación fija del volumen de almacenamiento

```text
DISCO / SISTEMA DE FICHEROS

 [Nodo-i Raíz (/)] ──► Lee bloques de /
                           │
                           ▼
                 Búsqueda de "usr" ──► Obtiene Nodo-i de /usr
                                                 │
                                                 ▼
                                        Lee bloques de /usr
                                                 │
                                                 ▼
                                       Búsqueda de "ast" ──► Obtiene Nodo-i de /usr/ast
                                                                       │
                                                                       ▼
                                                              Lee bloques de /usr/ast
                                                                       │
                                                                       ▼
                                                             Búsqueda de "mbox" ──► Obtiene Nodo-i final
                                                                                            │
                                                                                            ▼
                                                                                   Acceso a los Datos
```
* **Nota:** Todo directorio recién creado contiene automáticamente dos entradas especiales:

    * `.` : Apunta al nodo-i del directorio actual.

    * `..` : Apunta al nodo-i del directorio padre.

#### Ficheros Compartidos y Tipos de Enlaces
Al compartir ficheros entre directorios de distintos usuarios, la estructura de árbol del sistema de ficheros evoluciona a un **Grafo Acíclico Dirigido (DAG)**

```text
                      [ Nodo-i del Fichero Real ]
                               ▲       ▲
         ┌─────────────────────┘       └─────────────────────┐
         │ (Nodo-i N.º 42)                                   │ (Nodo-i N.º 42)
┌─────────────────┐                                 ┌─────────────────┐
│ Entrada dir A:  │                                 │ Entrada dir B:  │
│  "archivo.txt"  │                                 │  "enlace_duro"  │
└─────────────────┘                                 └─────────────────┘
         ▲                                                   ▲
         └────────────────── Enlace Duro ────────────────────┘

──────────────────────────────────────────────────────────────────────────

┌──────────────────┐       ┌─────────────────┐      ┌─────────────────┐
│ Entrada dir C:   │ ──►   │ Fichero de Tipo │ ──►  │ Nodo-i Original │
│ "enlace_soft"    │       │ Enlace (Ruta)   │      │ (Ruta absoluta) │
└──────────────────┘       └─────────────────┘      └─────────────────┘
         ▲                                                   ▲
         └──────────────── Enlace Simbólico ─────────────────┘
```


#### 1. Enlaces Duros (Hard Links)
* La nueva entrada de directorio apunta directamente al mismo número de nodo-i que el fichero original.

* Incremente el **contador de enlaces** (link count) almacenado en el nodo-i

* **Borrado seguro**: Si un usuario elimina su entrada, el archivo **no se borra físicamente** si el contador de enlaces es mayor que 1 (solo se decrementa el contador y se borra su entrada en el directorio)

* **Limitación:** No pueden cruzar diferentes sistemas de archivos/particiones

#### 2. Enlaces Simbólicos (Soft / Symbolic Links)
* Fichero especial que almacena como contenido una cadena de texto con la ruta de acceso (relativa o absoluta) hacia el archivo objetivo

* Posee su propio nodo-i independiente

* **Comportamiento ante borrado:** Si el dueño elimina el fichero original, el enlace simbólico permanece apuntando a una ruta inexistente (enlace roto/huérfano)

* **Ventajas:** Pueden referenciar ficheros en otros sistemas de archivos o incluso en recursos de red remotos

* **Inconvenientes:** Incurren en un consumo extra de I/O (requieren leer el bloque del enlace e interpretar la ruta)

### 9. Gestión del Espacio Libre
Para asignar bloques cuando se crean o amplían ficheros, el sistema debe llevar el control de cuáles están libres mediante dos estructuras principales:

```text
A) LISTA ENLAZADA DE BLOQUES LIBRES:
   [ Bloque Libre 1 ] ──► [ Bloque Libre 2 ] ──► [ Bloque Libre 3 ] ──► NULL
   (Contiene array con direcciones de otros N bloques libres)

B) MAPA DE BITS (BITMAP):
   Bloques:  [ 0 ][ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ][ 7 ]
   Estado:   [ 1 ][ 1 ][ 0 ][ 0 ][ 1 ][ 0 ][ 0 ][ 1 ]   (1 = Libre, 0 = Ocupado)
```

### 10. Fiabilidad del Sistema de Ficheros
La información en el almacenamiento persistente es crítica; su pérdida suele ser irreversible. El sistema de ficheros debe estar preparado para gestionar fallos físicos (bloques defectuosos) y lógicos (inconsistencias por caídas del sistema)

#### 1. Gestión de Bloques Defectuosos $(Bad Blocks)$
Dado el alto coste de fabricar discos libres de errores, casi todas las unidades contienen sectores defectuosos


```text
SOLUCIÓN HARDWARE:
[ Petición E/S ] ──► [ Controlador de Disco ] ──► ¿Bloque Defectuoso?
                                                        │
                                             Si ────────┴──────── No
                                             ▼                    ▼
                                  [ Redirige a Bloque ]    [ Lee Bloque ]
                                  [   de Repuesto     ]    [  Original  ]

SOLUCIÓN SOFTWARE:
[ Lista de Bloques Libres ] ──► (Asigna bloques a Ficheros Normales)
                                      ▲
[ Fichero de "Bad Blocks" ] ──────────┘ (Aísla los bloques dañados para no usarlos jamás)
```

* **Solución Hardware:** El controlador del disco mantiene una tabla de remapeo. Cuando se detecta un bloque defectuoso, lo redirige automáticamente a un sector de repuesto reservado en el mismo cilindro/disco

* **Solución Software:** El sistema de ficheros crea un fichero especial oculto que asigna y reserva todos los bloques defectuosos. De este modo, quedan excluidos de la lista de bloques libres

#### 2. Copias de Seguridad (Backups)
Para prevenir pérdidas masivas por fallos catastróficos del soporte:

* **Duplicación en Espejo (Física):** Dos unidades donde la zona de datos de una se copia periódicamente en la zona de reserva de la otra

* **Volcados Incrementales:** Partiendo de una copia completa inicial, solo se vuelcan los ficheros modificados a partir de la fecha de la última copia

#### 3. Coherencia e Integridad (File System Checking)
el sistema sufre una caída repentina (corte eléctrico, panic), los bloques modificados en memoria RAM que no se escribieron en disco pueden dejar al sistema de archivos en estado inconsistente. Para repararlo se emplean herramientas como ``fsck (en UNIX/Linux)

#### A) Comprobación de Bloques
Construye dos contadores en RAM inicializados a `0` para cada bloque de disco:

1. **Contador 1:** Veces que el bloque aparece en algún fichero (escaneando nodos-i).

2. **Contador 2:** Veces que el bloque aparece en la lista/mapa de bloques libres

| Caso | Contador Fichero | Contador Libre | Estado / Error Detectado | Acción Correctiva del Sistema |
| :--- | :--- | :--- | :--- | :--- |
| **Consistente** | $1$ | $0$ | El bloque pertenece a un fichero. | Ninguna. |
| **Consistente** | $0$ | $1$ | El bloque está libre. | Ninguna. |
| **Bloque Perdido** | $0$ | $0$ | Espacio desperdiciado (no asignado a nadie). | Se añade el bloque a la lista de libres. |
| **Libre Duplicado** | $0$ | $>1$ | Presente múltiples veces en la lista de libres. | Reconstruir la lista de bloques libres. |
| **Bloque Duplicado** | $>1$ | $0$ | **Severo:** Dos ficheros reclaman el mismo bloque. | Duplicar el bloque, asignar la copia a uno de los ficheros e informar al usuario. |
|

#### B) Comprobación de Directorios
Recorre recursivamente la estructura arborescente desde `/` contando cuántas entradas de directorio apuntan a cada nodo-i. Luego compara este valor con el contador de enlaces (link count) registrado dentro del propio nodo-i

```text
       ┌─────────────────────────────────────────────────────────┐
       ▼                                                         │
[ Contador en Nodo-i ] ◄─── ¿Coinciden? ───► [ Conteo Real en Directorios ]
                               │
                    Si ────────┴──────── No
                    ▼                    ▼
              [ Correcto ]       [ ERROR DE ENLACES ]
```
* **Contador en nodo-i > Entradas reales:** 
    * Error no crítico, pero desperdicia espacio. Si se borra el fichero, la cuenta nunca llegará a 0 y no se liberará. 
    * **Solución:** Ajustar la cuenta del nodo-i al valor real

* **Contador en nodo-i < Entradas reales:**
    * **Error catastrófico**. Si se elimina una entrada, la cuenta del nodo-i llega a 0 y libera los bloques de datos, dejando al resto de entradas apuntando a un nodo-i marcado como libre (corrupción de datos)
    * **Solución:** Forzar que el contador del nodo-i adopte el número real de entradas

### 11. Rendimiento del Sistema de Ficheros
Debido a que los discos son órdenes de magnitud más lentos que la memoria RAM, la optimización de las operaciones de E/S es crítica

#### Técnicas Principales de Optimización
```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                      TÉCNICAS DE RENDIMIENTO                           │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 1. Caché de Disco (Buffer Cache) ──► Bloques en RAM (Uso de SYNC)      │
 │ 2. Agrupación de Bloques        ──► Bloques del archivo en un cilindro │
 │ 3. Proximidad de Nodos-i        ──► Nodos-i cerca de sus datos (Ext2/3)│
 │ 4. Entrelazado (Interleaving)   ──► Salto rotacional entre bloques     │
 └────────────────────────────────────────────────────────────────────────┘
```

1. **Caché de Disco / Buffer Cache:** Reserva una zona de la memoria RAM para mantener los bloques de datos e índices más solicitados.

* *Escritura diferida:* Las modificaciones se realizan en RAM y se vuelcan a disco periódicamente (en UNIX mediante la llamada al sistema `sync` o `bdflush`/`pdflush`)

2. **Planificación de Disco:** Reordena las peticiones de lectura/escritura pendientes para minimizar los desplazamientos del brazo del disco (ej. algoritmos ELEVATOR/SCAN)

3. **Agrupación y Proximidad de Datos:**
    * Intentar asignar bloques contiguos dentro de la misma pista o cilindro

    * Colocar la tabla de **nodos-i cerca de sus bloques de datos correspondientes**: como hace el sistema de archivos Ext/2, Ext/3... evitando desplazamientos largos del cabezal

4. **Entrelazado (Interleaving):** Considera la velocidad de rotación del disco frente al tiempo de procesamiento de la CPU. Si el procesador tarda $X$ ms en procesar un bloque, los bloques lógicos consecutivos se posicionan a cierta distancia angular en el disco físico para estar justo bajo el cabezal al finalizar el procesamiento
