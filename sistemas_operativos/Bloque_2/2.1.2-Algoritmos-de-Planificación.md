# 2.1.2 Métrica de Evaluación de Algoritmos
La elección de un algoritmo de planificación depende de las prioridades del sistema operativo. Se evalúan mediante cinco parámetros clave:
```text
MÉTRICAS DE EVALUACIÓN
 ┌─────────────────────────┴─────────────────────────┐
 │ MAXIMIZAR                                         │ MINIMIZAR
 ├─ Uso de CPU (%)                                   ├─ Tiempo de Espera (E)
 └─ Productividad / Rendimiento (Throughput)         ├─ Tiempo de Retorno / Finalización (F)
                                                     └─ Penalización (P)
```

1. **Uso de la CPU (Processor utilization):** Porcentaje de tiempo que la CPU ejecuta procesos de usuario (habitualmente entre un 40% y 90%).

2. **Productividad (Throughput):** Número de ráfagas de CPU (o procesos completos) finalizados por unidad de tiempo.

3. **Tiempo de Espera ($E$):** Tiempo acumulado que una ráfaga/proceso permanece en la cola de preparados (excluye el tiempo de ejecución en CPU y la ejecución de E/S activa).

4. **Tiempo de Retorno / Finalización ($F$):** Tiempo total transcurrido desde que se crea el proceso hasta que finaliza en el sistema:
$$F = E + t \quad \text{o bien} \quad F = \text{Tiempo de Salida} - \text{Tiempo de Llegada}$$
(donde $t$ es el tiempo puro de CPU que necesita la ráfaga).

5. **Penalización ($P$):** Medida adimensional que evalúa la degradación sufrida por un proceso independientemente de su duración:
$$P = \frac{E + t}{t} = \frac{F}{t}$$

> **Compromiso del SO:** Maximizar el uso de CPU y el rendimiento requiere minimizar las llamadas al planificador (menos cambios de contexto). Sin embargo, esto perjudica los tiempos de respuesta de los procesos individuales. Los sistemas por lotes priorizan la productividad; los sistemas interactivos priorizan la respuesta rápida

## 2.1.3 Primero en Entrar, Primero en Salir (FIFO / FCFS)
Asigna la CPU al proceso que lleva más tiempo en la cola de preparados. La selección se gestiona con una cola FIFO estándar.

```text
COLA DE PREPARADOS: [ P8 ] ◄── [ P4 ] ◄── [ P2 ]  ──►  CPU: [ P7 ]
                       (Final)                 (Frente)
```
* **Funcionamiento:** Cuando un proceso entra a la cola de preparados, su BCP se coloca al final. Al liberarse la CPU, se le otorga al proceso del frente.

* **Tipo:** No apropiativo (el proceso mantiene la CPU hasta que se bloquea voluntariamente o termina)

* **Efecto sobre los procesos:** Efecto Convoy (los procesos cortos sufren esperando a que terminen los procesos largos con mucho uso de CPU)

## 2.1.4 Turno Rotatorio (Round Robin - RR)
Diseñado para **sistemas interactivos de tiempo compartido**. Asigna a cada proceso una cuota de tiempo fija de ejecución denominada cuanto ($q$)

```text
EXPIRACIÓN DEL CUANTO (Reinterrupción de Reloj)
                              ┌──────────────────────────────────┐
                              │                                  ▼
COLA DE PREPARADOS: [ P7 ] ◄──┴── [ P8 ] ◄── [ P4 ]  ──►  CPU: [ P2 ]
                       (Final)                 (Frente)
```
* **Mecanismo**
1. El sistema operativo asigna la CPU al proceso del frente de la cola de preparados.
2. Si el proceso agota su cuanto, una **interrupción de reloj** le arrebata la CPU, lo coloca al final de la cola y pasa el turno al siguiente
3. Si el proceso se bloquea o termina antes de agotar su cuanto, libera la CPU de inmediato
    * Tipo: **Apropiativo** (Expulsivo por tiempo)

## 2.1.5 Selección y Gestión del Tamaño del Cuanto ($q$)
El rendimiento del algoritmo Round Robin depende del valor elegido para el cuanto:
| Tamaño del Cuanto ($q$) | Comportamiento | Problema Principal |
| :--- | :--- | :--- |
| **Excesivamente Grande** | Degenera en un comportamiento tipo FIFO. | Pésimo tiempo de respuesta en entornos interactivos. |
| **Excesivamente Pequeño** | La CPU se dedica mayoritariamente a la conmutación de contexto. | Gran sobrecarga de gestión (*overhead*); cae la productividad. |
| **Óptimo ($\approx 10 - 100\text{ ms}$)** | Más largo que la mayoría de las peticiones interactivas cortas. | Mantiene buena respuesta sin penalizar en exceso el uso de CPU. |
|

## 2.1.6 Prioridad al Más Corto (Shortest Job First - SJF)
Algoritmo pensado originalmente para entornos en lote (batch) donde se conoce o calcula el tiempo estimado de ejecución de los procesos. Selecciona siempre el proceso listo con el tiempo de ráfaga más corto

```text
COLA DE PREPARADOS (Ordenada por duración):
[ P3 (12ms) ] ◄── [ P1 (8ms) ] ◄── [ P2 (3ms) ]  ──►  CPU: [ P4 (Ejecutando) ]
```

* **Tipo:** No apropiativo (el proceso seleccionado mantiene la CPU hasta finalizar o bloquearse).

* **Propiedad Clave: Minimiza el tiempo de finalización/espera promedio** para un conjunto de ráfagas disponibles simultáneamente

* **Inconvenientes:**

    * Penaliza gravemente a los procesos largos

    * **Inanición (Starvation):** Posible si siguen llegando procesos cortos de forma continua.

    * Requiere conocer la duración de las ráfagas con antelación

## 2.1.7. Tiempo Restante Más Corto (Shortest Remaining Time - SRT / SRTN)
Es la versión **apropiativa (expulsiva) de SJF**. Cuando un nuevo proceso entra en la cola de preparados, el planificador evalúa si su estimación es menor que el tiempo de CPU que le resta por ejecutar al proceso en curso

```text
NUEVO PROCESO: [ P_nuevo (2ms) ] ──┐
                                  ▼
                    ¿Tiempo restante P_actual (5ms) > 2ms?
                                  │
                       Si ────────┴──────── No
                       ▼                    ▼
             [ Expulsa a P_actual ]   [ Continúa P_actual ]
```

* Tipo: **Apropiativo**

* **Comportamiento:** Proporciona excelentes tiempos de respuesta para ráfagas muy cortas.

* **Punto Débil:** Un número excesivo de procesos cortos puede provocar continuos cambios de contexto (overhead) que degradan el rendimiento general del sistema

* **Inanición:** Posible para procesos de larga duración

## 2.1.8 Tasa de Respuesta Más Alta (Highest Response Ratio Next - HRN)
Estrategia propuesta por Brinch Hansen para corregir las deficiencias de SJF (evitar el retraso indefectible de los trabajos largos sin perder la agilidad en los cortos)

Calcula una prioridad dinámica para cada proceso en el momento de seleccionar:

$$\text{Prioridad} = \frac{\text{Tiempo de Espera} + \text{Tiempo de Servicio}}{\text{Tiempo de Servicio}}$$

* **Mecanismo:**

    * **Efecto Trabajos Cortos:** Al estar el tiempo de servicio en el denominador, los trabajos cortos obtienen mayor prioridad de entrada.

    * **Efecto Trabajos Largos:** A medida que un proceso largo acumula tiempo de espera en el numerador, su prioridad sube gradualmente hasta forzar su ejecución.

* Tipo: **No apropiativo**

* **Inanición: NO** (El envejecimiento en la cola garantiza que todos los procesos se ejecuten).

## 2.1.9 Colas Multinivel con Retroalimentación (Multilevel Feedback Queues - MLFQ)
Es un **mecanismo adaptativo** diseñado para clasificar procesos automáticamente sin conocer previamente sus necesidades de CPU ni su patrón de comportamiento

```text
NIVEL 0 (Alta Prioridad):    [ Cola RR (q corto: 10ms) ] ──► (Expira cuanto) ─┐
                                                                              │
NIVEL 1 (Prioridad Media):  [ Cola RR (q medio: 20ms) ] ◄─────────────────────┘
                                                      ──► (Expira cuanto) ──┐
                                                                            │
NIVEL 2 (Baja Prioridad):   [ Cola RR (q largo: 80ms) / FCFS ] ◄────────────┘
```

### Reglas de Funcionamiento
1. **Punto de Entrada:** Todo proceso nuevo entra al final de la cola de mayor prioridad (Nivel 0) con un cuanto $q$ pequeñ

2. **Degradación por Cómputo:** Si el proceso consume la totalidad de su cuanto sin bloquearse, desciende a la cola del siguiente nivel inferior (que suele ofrecer un cuanto $q$ más amplio pero menor prioridad)

3. **Favorecimiento a E/S:** Si un proceso libera la CPU voluntariamente por E/S antes de agotar su cuanto, abandona la red o mantiene/sube su nivel de prioridad

4. **Criterio de Selección:** Un nivel solo se ejecuta si todas las colas de nivel superior están vacías. Si llega un proceso a un nivel superior, expulsa al proceso actual del nivel inferior

### Propiedades
* **Adaptativo:** Un proceso que cambia de estar orientado a CPU a estar orientado a E/S recupera rápidamente posiciones de alta prioridad

* **Favoritismo:** Beneficia a los procesos cortos y a los interactivos o de mucha E/S (favoreciendo el paralelismo con periféricos)

* **Inanición:** Posible para procesos muy largos si la tasa de llegada de procesos cortos a las colas superiores es muy alta


## Cuadro Comparativo
| Algoritmo | Tipo | Criterio de Selección | Inanición | Principal Ventaja |
| :--- | :--- | :--- | :--- | :--- |
| **SJF** | No apropiativo | Ráfaga total más corta ($e$). | **Sí** | Minimiza el tiempo medio de finalización. |
| **SRT** | Apropiativo | Tiempo restante más corto ($s - e$). | **Sí** | Respuesta óptima para procesos muy cortos. |
| **HRN** | No apropiativo | Tasa de respuesta $P = \frac{E + s}{s}$. | **No** | Equilibrio entre procesos largos y cortos. |
| **MLFQ** | Apropiativo | Nivel de cola / Cuanto expirado. | **Sí** | Adaptativo; no requiere conocer duraciones previas. |
|
