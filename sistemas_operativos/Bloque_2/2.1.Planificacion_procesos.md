## 1. Conceptos Fundamentales de la Planificación (Scheduling)
La **planificación** es el conjunto de políticas y mecanismos del Sistema Operativo encargados de decir **cuanto, en que orden y durante cuanto timepo** se asignan los recursos del sistema (CPU, memoria, dispositivos) a los procesos
* **Mecanismos**: Las herramientas técnicas y estructuras de datos con las que se lleva a cabo la planificación; ej: colas de procesos
* **Políticas**: Las reglas o filosofías que determinan los objetivos a conseguir (ej reparto de la CPU)

## 2. Niveles o Tipos de Planificación
El sistema Operativo gestiona el flujo de los procesos en 3 niveles termporales diferenciados:
```text
┌────────────────────────────────────────────────────────────────────────┐
│                   PLANIFICADOR A LARGO PLAZO                           │
│     Decide qué trabajos por lotes entran desde disco al sistema.       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   PLANIFICADOR A MEDIO PLAZO (Swapper)                 │
│     Intercambia procesos entre Memoria Principal y Secundaria (Disco). │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   PLANIFICADOR A CORTO PLAZO (CPU / Dispatcher)        │
│     Selecciona el proceso de la Cola de Listos que usará la CPU.       │
└────────────────────────────────────────────────────────────────────────┘
```

### A. Planificación a Largo Plazo
* **Función**: Controla el grado de multiprogramación decidiendo **cuando se admite e introduce un nuevo proceso**
* **Frecuencia**: Muy **baja**. Al ejecutarse con poca frecuencia , puede permitirse el uso de **algoritmos complejos**
* **Objetivo principal**: Mantener una **mezcla equilibrada** de trabajos
    * Procesos limitados por la CPU
    * Procesos limitados por E/S
* **Comportamiento dinámico**:
    * Si el uso de la CPU es bajo -> Admite más trabajos para aumentar la cola de listos
    * Si la CPU está muy cargada -> Reduce la admisión de nuevos trabajos para proteger el timepo de respuesta

### B. Planificación a Medio Plazo (Swapper)
* **Función**: Governan las ttransiciones de procesos entre la **memoria principal (RAM)** y la **memoria secundaria (disco)** mediante el mecanismo de intercambio
* **Frecuencia**: Intermedia
* **Objectivo principal**: Evitar que la memoria RAm se llene de procesos bloqueados mientras la CPU queda ociosa
* **Criterios de intercambio**
    * Pasa a disco duro (memoria secundaria) procesos en estado **Bloqueado**
    * Trae a Ram procesos en estado **Suspendido-Listo** con preferencia sobre procesos Suspendido-bloqueado

### C. Planificación a Corto Plazo (CPU)
* **Función**: Selecciona que proceso en estado Listo pasará inmediatamente a la CPu para ejecutarse
* **Frecuencia**: Muy **alta**. Requiere algoritmos rápidos y eficiencias de bajo coste

## 3. El Despachador (Dispatcher)
El **Dispatcher** es el componente hardware/software del Sistema Operativo que ejecuta la decisión tomada por el planificador a corto plazo

```text
[ Planificador a Corto Plazo ] ──( Selecciona Proceso B )──► [ Dispatcher ]
                                                                   │
                                                                   ├─► Realiza Cambio de Proceso
                                                                   ├─► Conmuta a Modo Usuario
                                                                   └─► Salta a la dirección del PC
```

### Eventos que Invocan al Dispatcher:
1. El procesoen ejecución finaliza o se bloquea (por E/S, `WAIT` en semáforo etc)
2. El Sistema Operativo ordena el bloqueo explícito del proceso en ejecución
3. El proceso en ejecución **agota su cuanto** detiempo de CPU
4. Un proceso pasa de cualquier estado al estado de **Listo**

> **Impacto en el Rendimiento:** Cuantas menos veces se invoque al dispatcher, más tiempo de CPU se dedica a las aplicaciones de usuario (puesto que el cambio de proceso genera sobrecarga o overhead).

## 4. Enfoques de Activación del Dispatcher según el Tipo de Sistema
| Tipo de Sistema | Eventos de Invocación | Enfoque | 
| -- | -- | -- |
| **Sistema por Lotes (Batch)** | Solo eventos **1 y 2** (el proceso cede la CPU de forma voluntaria al bloquarse o terminar) | Muestra **preferencia por el proceso en ejecución**. Maximia el uso eficiente del procesador |
| **Sistema de Tiempo Compartido** | eventos **1,2,3 y 4** (el So puede expropiar la CPU al agotar el cuanto o llegar un proceso listo) | Muestra preferencia por el **conjunto global de todos los procesos** evitando que procesos intesivos en cómputo monopolicen la CPU
|

### Tabla comparativa de los 3 Niveles de Planificación
| **Criterio** | **Largo Plazo** | **Medio Plazo** | **Corto Plazo** |
| -- | -- | -- | --| 
| **Frecuencia de invocación** | Baja | Media | Muy alta | 
| **Recurso gestionado** | Entrada al sistema | Memoria Principal / Disco | CPU |
| **Estado objetivo** | Nuevo -> Listo | Suspendido -> Activo | Listo -> Ejecución | 
| **Complejidad del algorítmo** | Alta | Media | Baja (Muy optimizado) |
|

## 3. Objetivos y Criterios de Planificación
El objetivo principal de la planificación de la CPu es distribuir el tiempo del procesador de forma que se maximice la eficiencia general del sistema. Dado que existen múltiples necesidades, los criterios de evaluación se agrupan según dos clasificaciones principales:

### A. Clasificación según la Orientación (Usuario VS Sistema)
* **Orientados al Usuario**: Miden el comportamiento del sistema tal como lo perciben los usuarios o los procesos
> Ejemplo: **Tiempo de Respuesta (Response Time)**, que es el intervalo transcurrido desde que se emite una solicitud interactiva hasta que el sistema comienza a mostrar el resultado.
* **Orientados al Sistema**: Evaluan el uso efectivo y óptimo del procesador
> Ejemplo: **Productividad (Throughput)**, que es el número de procesos completados por unidad de tiempo.

### B. Clasificación según la Medición (Cuantitativos vs. Cualitativos)
* **Relativos al Rendimiento (Cuantitativos)**: Son medibles y analizables numéricamente (ej: tiempo de respuesta)

* **No Relativos al Rendimiento (Cualitativos)**: Miden aspectos de comportamiento abstracto
> Ejemplo: **Previsibilidad**, que garantiza que un proceso tarde aproximadamente el mismo tiempo y mantenga el mismo coste con independencia de las variaciones de carga en el sistema.

### C. Objetivos Globales que debe cumplir una Política de Planificación
1. **Equidad (fairness)** : Tratar a todos los procesos por igual y evitar la postposiciń indefinida (inación /starvation)

> Técnica de Solución: **Envejecimiento (Aging)**, que consiste en aumentar progresivamente la prioridad de un proceso a medida que pasa tiempo esperando en la cola.

2. **Eficiencia**: Maximizar la ocupación de la CPU reduciendo al mínimo el overhead o gasto extra derivado a la propia gestión del SO

3. **Optimizar le tiempo de respuesta**: Garantizar tiempos rápidos para los usuarios interactivos

4. **Garantizar Previsibilidad**: Ofrecer un rendimiento constante para evitar variaciones drásticas en la ejecución

5. **Maximizar la Productividad**: Favorecer procesos que liberen rápidamente recursos críticos o aquellos con patrones de ejecución eficientes

> **Compromiso y Conflicto:** Es imposible optimizar todos los criterios a la vez. Por ejemplo, mejorar el tiempo de respuesta requiere cambios de proceso frecuentes, lo que aumenta la sobrecarga y reduce la productividad global del sistema.

### 4. Planificación Apropiativa y No Aprotiativa
| Criterio | Planificación No Apropiativa | Planificación Apropiativa | 
| -- | -- | -- |
| **Definición** | Una vez asignada la CPu al proceso , este la conserva hasta que termina su ráfaga o realiza una E/S | El SO puede arrebatar (apropiar) la CPU al proceso en ejecución si llega uno de mayor prioridad o se agota su cuanto | 
| **casos de Uso** | Sistemas por lotes (Batch) | Sistemas de Tiempo Compartido y Tiempo real |
| **Ventajas** | •Menor sobrecarga (overhead). • Tiempos de respuesta más predecibles. • Más "justo" al no interrumpir ejecuciones en curso. | • Respuesta rápida para prioridades altas. • Evita monopolizaciones de la CPU. • Mantiene tiempos de respuesta interactivos |
| **Desventajas** | Los procesos largos bloquean indebidamente a los procesos cortos | Mayor gasto de CPU debido al almacenamiento recurrente de contextos y mantenimiento de memora| 
|  

### 5. El Reloj de Interrupciones
El **reloj de interrupciones** es un mecanismo fundamental que permite al Sistema Operativo arrebatar el control de la CPU a un proces de usuario para evitar que este la monoplice
```text
[ Proceso de Usuario en CPU ]
                    │
                    ▼
┌───────────────────────────────────────┐
│ Interrupción Hardware de Temporizador │ ──► (Ocurre cada T milisegundos)
└───────────────────┬───────────────────┘
                    │
                    ▼
 ┌─────────────────────────────────────┐
 │  Manejador de Interrupciones del SO │ ──► El SO toma el control
 └──────────────────┬──────────────────┘     (Comprueba el cuanto o prioridades)
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
 [ Reanuda el mismo ]   [ Cambia a otro ]
```

### Eventos que hacen perder la CPU a un proceso:
1. Liberación voluntaria (termina la ejecución o se bloquea por E/S semáforo)
2. Ocurrencia de una interrupción de reloj que agota el tiempo asignado
3. Ocurrencia de una interrupción externa de hardware de mayor prioridad

### Reloj Hardware vs. Reloj de Interrupciones
$$\text{Frecuencia } (f) = \frac{1}{\text{Periodo } (T)}$$

```text
+-------------------------------------------------------------------------+
| RELOJ HARDWARE (GHz)                                                    |
| Mide los ciclos básicos de la CPU (Ej: 4,0 GHz = 4.000.000.000 Hz)      |
+-------------------------------------------------------------------------+
       │  (Contiene millones de ciclos por cada interrupción)
       ▼
+-------------------------------------------------------------------------+
| RELOJ DE INTERRUPCIONES (Hz)                                            |
| Marca el ritmo al que el SO recupera el control (Ej: 250 Hz = 4 ms)     |
+-------------------------------------------------------------------------+
       │  (Agrupa miles de interrupciones)
       ▼
+-------------------------------------------------------------------------+
| CUANTO DE CPU (Quantum)                                                 |
| Tiempo total asignado a un proceso antes de ser expulsado               |
+-------------------------------------------------------------------------+
```

* **Reloj Hardware Físico**: Trabaja a frecuencias del orden de los $GHz (10^9 HZ)$. Marca el pulso de las instrucciones elementales
* **Reloj de Interrupciones**: Funciona a frecuencias del orden de los **Hz** ej (100Hz - 1000 Hz) PRoduce un pulso cada cierto tiempo $T$ para que el procesador no pierda tiempo ejecutando únicamente código del manejador

## 6. Planificación por Prioridades
La mayoría de las políticas de planificación asignan a cada proceso una **prioridad** (un valor numérico). El planificador simepre seleccionapara ejecución el prceso en estado preparado para que posea el nivel de prioridad más alto

## Clasificación por Prioridades
* **Origen de la Asignación**
    * **Automáticas**: Determinadas internamente por el propio Sistema Operativo en función del tipo de proceso o uso de recursos
    * **Externas**: Asignadas manualmente por el usuario o administración del sistema
    * **Arbitrarias**: Asignaciones sin criterio de importancia real, usadas solo cuando el SO necesita desempatar procesos
* **Dinámica temporal**
    * **Prioridades Estáticas**: permanece inalterada durante toda la vida del proceso
        * **Ventaja**: Implementación sencilla y sobrecarga (overhead) muy baja
        * **Inconveniente**: No responde a cambios en el entorno del sistema
    * **Prioridades Dinámicas**
        * **Ventaja**: Gran adaptabilidad y respuesta eficiente del sistema
        * **Inconveniente**: Mayor comlejidad y gasto ex tra de cómputo para recalcularlas

## 7. Métricas de Evaluación de los Algoritmos de Planificación
Para evaluar y comparar el comportamiento de las distintas políticas de planificación de la CPu se emplean métricas diversas 

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        TIEMPO DE RETORNO / FINALIZACIÓN (F)            │
│ ┌─────────────────────────────┬──────────────────────────────────────┐ │
│ │  Tiempo de Espera (E)       │  Tiempo de Ejecución / CPU (t)       │ │
│ └─────────────────────────────┴──────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
  ▲                                                                    ▲
  │                                                                    │
  Llegada al Sistema                                             Salida del Sistema
```
### Métricas de Rendimiento del Sistema
1. **Ocupación de CPU (Processor Utilization):** Porcentaje de tiempo que el procesador ejecuta código de usuario. En sistemas reales oscila entre el 40% y el 90%.

2. **Productividad (Throughput):** Número de ráfagas completadas o número de procesos finalizados por unidad de tiempo.

### Métricas de Tiempo de los Procesos
1. **Tiempo de Espera o Respuesta ($E$):** Tiempo total que una ráfaga o proceso permanece en la cola de preparados esperando a que se le asigne la CPU.(Nota: No incluye el tiempo dedicado a ejecutar E/S, pero sí las esperas en colas de dispositivos).

2. **Tiempo de Finalización o Retorno ($F$):** Tiempo total transcurrido desde que el proceso entra en el sistema hasta que finaliza completamente.
$$F = E + t \quad \text{o bien} \quad F = \text{Tiempo de Salida} - \text{Tiempo de Llegada}$$
(Donde $t$ es el tiempo neto de ejecución en CPU).


3. **Penalización ($P$):** Relación adimensional entre el tiempo total en el sistema ($F$) y el tiempo de execution ($t$). Permite comparar procesos de distintas longitudes de forma justa:

$$P = \frac{E + t}{t} = \frac{F}{t}$$

**El Conflicto de Optimización:**

* **Objetivo general:** Maximizar la Ocupación de CPU y la Productividad; Minimizar el Tiempo de Espera, Tiempo de Finalización y la Penalización.

* **Compromiso:** Reducir los tiempos de espera exige conmutar procesos con alta frecuencia. Esto incrementa el overhead de la planificación, reduciendo la productividad global.

* **Sistemas por Lotes:** Priorizan la productividad.

* **Sistemas Interactivos:** Priorizan minimizar el tiempo de espera/respuesta.
