# 4.0 Memoria Virtual
## 4.1. Introducción y Conceptos Fundamentales
Las técnicas de asignación de memoria no contigua (paginación, segmentación y segmentación paginada) permiten implementar la **Memoria Virtual**: un esquema de gestión que posibilita la ejecución de procesos que no se encuentran totalmente ubicados en la memoria RAM

### Desafíos de Implementación
* **Minimazión de fallos de Página**: El sistema debe reducir la frecuencia con la que un proceso intenta acceder a una página no presente en RAM

* **Reducción del Tiepo Efectivo de Acceso (EAT)**: La paginación bajo demanda afecta directamente al rendimiento del sistema

* **Remplazo de Páginas y Asignación de Marcos**: Cuando la memoria física está llena se requiere una página , el sistema operativo debe decidir qué marco liberar

* **Control de la Hiperpaginación (Thrashing)**: Ocurre cuando el sistema dedica más tiempo a intercambiar páginas con el disco que a ejecutar instrucciones. Se combate mediante el principio de localidad, el modelo del **Conjunto de Trabajo (Working Set)** o el control de la **frecuencia de fallos de página**

## 4.2. Motivos y Ventajas de la Memoria Virtual
Cargar el espacio de direcciones lógicas completo de un proceso antes de su ejecución limita su tamaño a la capacidad de la memoria física disponible. Sin embargo, el análisis de programas reales demuestra que **raramente se necesita todo el código y los datos simultáneamente**:

1. **Tratamiento de Excepciones**: Código dieñado para errores poco frecuentes que casi nunca se ejecuta

2. **Estructura de Datos sobredimensionadas**: Declaración de matrices o tablas de símbolos con capacidades máximas (ej : 100 x 100) que en la práctica solo usan una pequeña fracción (10x10)

3. **Módulos u Opciones Opcionales**: Funcionalidades secundarias de un programa que el usuario utiliza rara vez

```text
┌─────────────────────────────────────────────────────────────────┐
│                 ESPACIO DE DIRECCIONES VIRTUALES                │
├──────────────┬──────────────────┬──────────────┬────────────────┤
│ Código Usado │ Tratamiento Error│ Datos Usados │ Estructura (*) │
└──────┬───────┴──────────────────┴──────┬───────┴────────────────┘
       │ (Solo se carga lo necesario)    │
       ▼                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│                    MEMORIA FÍSICA REAL (RAM)                    │
└─────────────────────────────────────────────────────────────────┘
```

### Ventajas de la Carga Parcial
* **Superación del Límite Físico:** Los programas ya no están restringidos por la RAM física. Los programadores pueden trabajar con un espacio virtual muy amplio sin preocuparse por la capacidad de la máquina

* **Mayor Grado de Multiprogramación**: Al ocupar menosRAM por proceso, caben más procesos simultáneamente, lo que incrementael rendimiento y la utilización de la CPU

* **Optimización de E/S**: Se reduce la cantidad de datos transferidos desde la memoria secundaria durante la carga e intercambio, acelerando la ejecución

### Definiciones Clave
* **Memoria Virtual:** Esquema donde el almacenamiento secundario se direcciona como si fuera parte de la memoria principal, separando la memoria lógica de la física.

* **Dirección Virtual: Dirección asignada a una ubicación en memoria virtual.

* **Espacio de Direcciones Virtuales ($V$):** Almacenamiento virtual asignado a un proceso

* **Espacio de Direcciones:** Rango de direcciones de memoria disponibles para un proceso

* **Dirección Real o Física:** Dirección de una posición de almacenamiento en la memoria RAM

## 4.3. Estrategias de Gestión de Memoria Virtual
Para cualquier esquema no contiguo (paginación, segmentación o segmentación paginada) que implemente memoria virtual, el sistema operativo debe definir tres estrategias clave

```text
Estrategias de Gestión ──┬── Obtención (Fetch)   ──► ¿CUÁNDO se trae una página/segmento?
                         ├── Colocación (Placement) ─► ¿DÓNDE se ubica en la RAM?
                         └── Reemplazo (Replacement)──► ¿QUÉ página se expulsa si la RAM está llena?
```
1. **Estrategias de Obtención (Fetch):**
* **Por Demanda:** La página o segmento se transfiere a RAM únicamente cuando el proceso en ejecución realiza una referencia explícita a ella
* **Anticipada (Paging /Prefetching)**: El sistema intenta predecir qué páginas o segmentos se necesitarán en el futuro cercano y los carga con antelación si hay espacio disponible

2. **Estrategias de Colocación (Placement):**
En **Paginación**, la decisión es inmediata: cualquier marco libre es válido
En **Segmentación**, se requieren algoritmos de búsqueda (First Fit, Best Fit, Worst Fit)

3. **Estrategias de Reemplazo (Replacement):**
Determinan qué página o segmento debe ser expulsado a disco para dejar espacio a una nueva entrada cuando la memoria principal está totalmente ocupada

## 4.4 Paginación bajo Demanda
Es un esquema similar a la paginación con intercambio (swapping), pero utiliza un **paginador perezoso (lazy pager)**: nunca carga una página a memoria a menos que sea estrictamente necesaria

```text
Proceso en Disco ──► [ Lazy Pager ] ──(Página requerida)──► Memoria RAM
                                    └──(Página no usada)──► Permanece en Disco
```
* **Diferencia conceptual**: Un swapper manipula procesos completos; un paper gestiona páginas individuales

* **Soporte Hardware:** Requiere que la entrada de la tabla de páginas disponga de un bit de presencia / válido-inválido

* `1` (Válido / Presente): La página está cargada en RAM
* `0` (Inválido / No Presente): La página está en disco. Si el proceso intenta acceder a ella, el hardware genera una excepción de Fallo de Página (Page Fault)

## 4.4.1. Estructuras de Tablas de Páginas
Como cada proceso puede tener un espacio de direcciones virtuales enorme, mantener tablas de páginas lineales contiguas en RAM resulta ineficiente o inviable

### A. Tablas de Páginas en Dos Niveles (Paginación Jerárquica)
Consiste en paginar la propia tabla de páginas. Existe un **Directorio de Páginas (o Tabla Raíz)** donde cada entrada apunta a una página que contiene un trozo de la tabla de páginas del usuario

```text
Dirección Virtual (32 bits):
┌────────────────────────┬────────────────────────┬────────────────────────┐
│  Índice Directorio p1  │    Índice Página p2    │    Desplazamiento d    │
│       (10 bits)        │       (10 bits)        │       (12 bits)        │
└───────────┬────────────┴───────────┬────────────┴───────────┬────────────┘
            │                        │                        │
            ▼                        │                        │
  Directorio de Páginas              │                        │
  ┌──────────────────┐               │                        │
  │ Entry -> Tabla p2│───────────────┼────────┐               │
  └──────────────────┘               │        │               │
                                     ▼        ▼               │
                         Tabla de Páginas de Usuario          │
                         ┌──────────────────┐                 │
                         │ Entry -> Marco f │─────────────────┼──────┐
                         └──────────────────┘                 │      │
                                                              ▼      ▼
                                                  Dirección Física Real:
                                                  ┌──────────────────┬───┐
                                                  │     Marco f      │ d │
                                                  └──────────────────┴───┘
```

#### Cálculo de ejemplo (Dirección de 32 bits, Páginas de 4 KiB):
* Desplazamiento ($d$): $12\text{ bits}$ ($2^{12} = 4096\text{ bytes}$)
* Páginas virtuales totales: $32 - 12 = 20\text{ bits}$ ($2^{20} = 1.048.576\text{ páginas}$)
* Si cada ETP ocupa $4\text{ bytes}$, la tabla completa ocuparía $4\text{ MB}$ contiguos.
* **Solución de 2 Niveles:** Se divide en $10\text{ bits}$ para el Directorio Raíz ($1024\text{ entradas} \times 4\text{ bytes} = 4\text{ KiB}$, exactamente 1 página) y $10\text{ bits}$ para la tabla de páginas de usuario.

### B. Tabla de Páginas Invertida
En lugar de crear una entrada por cada página del espacio virtual del proceso, **la Tabla de Páginas Invertida** mantiene **una única entrada por cada marco de página real de la RAM**

```text
Dirección Virtual: [ PID | Número de Página Virtual (p) | Offset (d) ]
                                    │
                                    ▼
                          Función Hash (PID, p)
                                    │
                                    ▼
                    Tabla de Páginas Invertida (RAM)
                    ┌───────┬────────┬───────┬─────────┐
                    │ Marco │  PID   │ Página│ Puntero │
                    ├───────┼────────┼───────┼─────────┤
                    │   i   │  104   │  p_3  │   --->  │ (Resolución de colisiones)
                    └───────┴────────┴───────┴─────────┘
```

* **Tamaño Fijo:** Su tamaño depende exclusivamente de la capacidad de la memoria RAM física, siendo independiente del número de procesos activos o del tamaño de sus espacios virtuales

* **Búsqueda por Hash:** Se aplica una función hash sobre el par (`PID`, `número_de_página`). Para gestionar las colisiones en la tabla hash, las entradas incluyen un puntero de encadenamiento.

* **Estructura de la Entrada:**
1. **Número de Página Virtual**.
2. **Identificador del Proceso (PID)**
3. **Bits de Control** (válido, modificado, referenciado, protección)
4. **Puntero de Cadena** (para resolver colisiones hash)

### 4.4.2. Gestión de un Fallo de Página (Page Fault)
Si un proceso intenta acceder a una dirección lógica cuya página no está cargada en memoria principal, la MMU (Memory Management Unit) detecta que **el bit de presencia/validez es inválido** `(0)`. Esto genera una excepción o trampa (trap) de fallo de página hacia el sistema operativo

```text
Proceso de usuario                 Sistema Operativo                      Disco
┌───────────────────┐              ┌──────────────────────┐             ┌────────┐
│ 1. Acceso a pag   │              │ 3. Consultar PCB:    │             │        │
│    inválida (0)   ├─(TRAP MMU)──►│    ¿Es legal?        │             │        │
└───────────────────┘              └──────────┬───────────┘             │        │
                                              │ (Sí, pero en disco)     │        │
                                              ▼                         │        │
┌───────────────────┐              ┌──────────────────────┐  4. Lectura │        │
│ 6. Reinstruir la  │◄─(Reanudar)──┤ 5. Actualizar TP:    │◄─de Página──┤        │
│    instrucción    │              │    Bit presencia = 1 │  (E/S)      │        │
└───────────────────┘              └──────────────────────┘             └────────┘
```

### Secuencia de Pasos para Servir un Fallo de Página:
1. **Comprobar Legalidad:** El SO consulta una tabla interna (asociada al PCB) para verificar si la dirección era legal (dentro del espacio virtual del proceso).
    1. Si es ilegal: Se aborta el proceso
    2. Si es legal: La página existe pero debe ser traída desde el disco
2. **Obtener MarcoLibre**: Se busca un marco de página libre en RAM (desde la lista de marcos libres)
3. **Programar Operación de Disco (E/S):** Se planifica la lectura de la página requerida desde la memoria secundaria (swap) hacia el marco asignado
4. **Actualizar Tablas**: Al finalizar la lectura de disco, se actualiza la entrada de la tabla de Páginas (ETP) fijando el **bit de presencia en `1`** (válido) y registrando el número de marco
5. **Reinicar la Instrucción**: Se restaura el contexto guardado (contador de programa, registros) del proceso y **se reorganiza la ejecución para repetir la misma instrucción** que causó el fallo. Ahora la página está presente en RAM de forma totalmente transparente

> **Paginación por Demanda Pura**: Caso extremo donde un proceso inicia su ejecución con cero páginas en RAM. La mismísima primera instrucción causa un fallo de página, e irá trayendo páginas únicamente a medida que las necesite. Gracias al **Principio de Localidad**, este esquema ofrece un rendimiento aceptable

### 4.4.3. Requisitos Hardware y Dificultades Arquitectónicas
Además de la Tabla de Páginas (con bits de presencia/protección) y la Memoria Secundaria (zona de swap), la paginación por demanda exige que el procesador sea capaz de **reiniciar cualquier instrucción interrumpida a mitad de su ejecución**

### El Problema de las Instrucciones Compuestas o Multidirección
Si un fallo de página ocurre al final de una instrucción de múltiples pasos, las fases previas ya pueden haber alterado operandos o registros

* Ejemplo de Instrucción de 3 Direcciones (`ADD A, B, C`):
1. Leer y decodificar `ADD`.
2. Leer operando `A`.
3. Leer operando `B`.
4. Sumar $A + B$.
5. Escribir resultado en `C` $\rightarrow$ ¡Fallo de página al escribir en C!
> Solución: Tratar el fallo, traer la página de `C`, actualizar la tabla y reiniciar la instrucción desde el paso 1 (volver a leer operando `A` y `B`).

> **Caso Crítico: Transferencias de Memoria Múltiple (`MVC` / Movimiento de Bloques):**
Instrucciones que mueven hasta 256 bytes entre zonas de memoria que se solapan. Si el fallo ocurre a mitad de la copia, los datos origen pueden haber sido sobreescritos parciales, imposibilitando repetir la instrucción directamente

### 4.4.4 Rendimiento de la Paginación bajo Demanda
El **Tiempo Efectivo de Acceso (EAT - Effective Access Time)** mide el impacto real de los fallos de página en el rendimiento del sistema.
$$\text{EAT} = (1 - p) \times \text{Tiempo Acceso RAM} + p \times \text{Tiempo Servicio Fallo Página}$$
Donde $p$ representa la probabilidad o tasa de fallos de página ($0 \le p \le 1$).

### Componentes del Tiempo de Servicio de Fallo de Página:
1. **Atender la interrupción** (Trampa, guardar contexto del proceso, verificar legalidad): $\sim 1 \text{ a } 100\ \mu\text{s}$.
2. **Lectura de página en Disco** (Espera en cola, tiempo de búsqueda, latencia y transferencia): $\sim 8\text{ ms} = 8.000.000\text{ ns}$.
3. **Reanudar el proceso** (Actualizar tablas, cambio de contexto, planificar CPU): $\sim 1 \text{ a } 100\ \mu\text{s}$.

```text
EAT (ns)
   ▲
   │                                   / (Impacto crítico si p sube)
   │                                 /
   │                               /
   │                             /
   │                           /
200│─────────────────────────/
   └─────────────────────────────────────────► Tasa de fallos de página (p)
    0                       1/400.000
```
### Ejemplo Práctico de Impacto de Rendimiento:
* **Tiempo de acceso a RAM ($t_{RAM}$):**$200\text{ ns}$ (incluyendo la traducción de tabla de páginas)
* **Tiempo de servicio de fallo de página ($t_{fallo}$): $8\text{ ms} = 8.000.000\text{ ns}$**
.$$\text{EAT} = (1 - p) \times 200 + p \times 8.000.000 = 200 + 7.999.800 \times p \quad (\text{en ns})$$

* **Caso 1:** Si $p = 0.001$ (1 fallo por cada 1.000 accesos):
$$\text{EAT} = 200 + 7.999,8 = 8.199,8\text{ ns} \approx 8,2\ \mu\text{s}$$
> El rendimiento cae un 40% respecto a la velocidad original.

* **Caso 2:  Para tolerar una degradación menor al 10% (EAT $\le 220\text{ ns}$):**:
$$200 + 7.999.800 \times p \le 220 \implies p \le \frac{20}{7.999.800} \approx \frac{1}{399.990}$$
> Se requiere tener menos de 1 fallo de página por cada 400.000 accesos a memoria.

### 4.4.5. Reemplazo de Páginas
Cuando aumenta el grado de multiprogramación, se puede llegar a una situación de **sobreasignación de memoria** (overallocating): la suma del número de páginas activas requeridas por los procesos supera la cantidad de marcos de página físicos libres en RAM

```text
PÁGINA DENTRO DE RAM
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
 Bit Modificación = 0       Bit Modificación = 1
  (Página No Modificada)      (Página Modificada / Dirty)
             │                           │
             ▼                           ▼
   Sustitución Directa        Escritura obligatoria en Disco
  (1 Transferencia E/S)          (2 Transferencias E/S)
```

### Rutina de Servicio con Algoritmo de Reemplazo:
1. Localizar en disco la página requerida.

2. Buscar un marco libre en RAM:
    * **Si hay un marco libre:** Se usa directamente.

    * **Si NO hay marcos libres:** Se aplica un **Algoritmo de Reemplazo de Páginas** para seleccionar un **marco víctima**.

3. **Optimización con Bit de Modificación (Dirty Bit)**:

    * Si la página víctima no fue modificada (`dirty bit = 0`), no es necesario escribirla en disco; el marco se sobrescribe directamente (1 transferencia E/S).

    * Si la página víctima fue modificada (`dirty bit = 1`), debe escribirse primero en el disco antes de cargar la nueva página (2 transferencias E/S)

4. Cargar la página deseada en el marco liberado y actualizar las ETPs.

5. Reanudar el proceso interrumpido.
