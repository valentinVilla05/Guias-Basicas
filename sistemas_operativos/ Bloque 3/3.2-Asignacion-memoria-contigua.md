# 3.2 Asignación de memoria Contigua
En la asignación contigua , cada programa debe ocupar un único bloque invisible y consecutivo de memoria principal
```text
┌──────────────────────────────────────────────────────────┐
│               SISTEMA OPERATIVO (RAM Baja)               │
├──────────────────────────────────────────────────────────┤
│                  Proceso A (Contiguo)                    │
├──────────────────────────────────────────────────────────┤
│                   Hueco Libre (Contiguo)                 │
├──────────────────────────────────────────────────────────┤
│                  Proceso B (Contiguo)                    │
└──────────────────────────────────────────────────────────┘
```
## 3.2.1 Particiones Estáticas o Fijas
La memoria principal se divide en regiones estáticas en el momento de generación del sistema. Cada región puede tener un tamaño diferente, pero su dimensión permanece inalterable

* **Traducciión y Carga absoluta**: Los primeros sistemas compilaban el código indicando una partición específica. Si la partición destino estaba ocupada, el proceso debía esperar aunq existieran otras libres, lo q diminuía la eficiencia

* **Carga Relativa y Reubicación Dinámica**: para que un proceso pueda encargarse en cualquier partición libre, los programas se compila asumiendo que empiezan el la dirección relatica `0`

### Mecanismos de Reubicación
* **Soporte Hardware (Registro Base)**: La CPu añade de forma transparente el valor del  **Registro Base** (direcciónfiscia de inicio de la partición) a toda direccion relativa generada por el programa

    $Dirección Física = Dirección Relativa + Registro Base$
* **Solución Software**: El enlazador incluye una lista de reasignación. Durante la carga, el sistema modifica directamente en el binario todas las instrucciones que referencian direcciones de memoria.

### Protección de Memoria
Se implementa mediante un **Registro Límite** (longitud del proceso o última dirección válida). El hardware verifica cada instrucción en tiempo de ejecución

$$\text{Si } (\text{Dirección Relativa} + \text{Registro Base}) > \text{Registro Límite} \longrightarrow \text{Trap / Excepción por violación de memoria}$$

> **Acceso a Servicios del SO:** La protección impide que un proceso llame directamente al código del SO. Debe realizar una **Llamada al Sistema** (System Call), pasando a modo kernel de forma controlada.

### Inconveniente principal
* **Fragmentación Interna**: Desperdicio de memoria producido cuando el tamaño del proceso es menor que el de la partición asignada. EL espacio sobreante dentro de la partición no puede ser utilizado por ningún otro proceso

## 3.2.3 Particiones Dinámicas
Las particiones se crean y ajustan dinámicamente en tiempo de ejecución. A cada proceso se le asigna exactamente la cantidad de memoria que requiere en el momento de su carga

```cpp
Evolución de la memoria:
[Proceso A] ──> [Proceso A | Proceso B | Proceso C] ──> (A termina) ──> [Hueco | Proceso B | Proceso C]
                                                                                ▲
                                                                     Fragmentación Externa
```

* **Ventaja:** Elimina por completo la fragmentación interna
* **Desventaja (Fragmentación Externa)**: Con el tiempo , la entrada y salida de procesos deja peequeños huecos de memoria dispersos. Aunq la suma total de los huecos sean grande, no pueden albergar un nuevo proceso por no ser contiguos
* **Compactación de Memoria***: Soluciona a la fragmentación externa que consiste en desplazar los procesos en ejecución hacia un extremo de la RAM para consolidar los huecos libres
    * **Inconveniente**: Consume tiempo intensivo de CPU, requiere congelar la ejecución del sistema y es inviable en **sistemas de tiempo real**

## 3.2.4 Gestión del Crecimiento de Datos y Pila (Stack)
Cuando un proceso requiere incrementar su espacio dinámico (memoria dinámica / heap o pila /stack)

1. **Asignación de Margen Extra**: Se asigna espacio adicional preventivo durante la carga inicial
2. **Crecimiento Convergente**: Se ubica el segmento de datos en el extremo inferior creciendo hacia arriba, y la pila en el extremo superior creciendo hacia abajo

```text
┌──────────────────────────────────────────────────────────┐
│ Código / Programa                                        │
├──────────────────────────────────────────────────────────┤
│ Datos / Heap (Crece hacia arriba ▲)                      │
├──────────────────────────────────────────────────────────┤
│                   Espacio Disponible                     │
├──────────────────────────────────────────────────────────┤
│ Pila / Stack (Crece hacia abajo ▼)                       │
└──────────────────────────────────────────────────────────┘
```

## 3.2.5 Registro de Ocupación de la memoria
En particiones dinámicas, el SO debe rastrear de forma eficiente los bloques libres y ocupados

```text
Memoria Fís: [ P1 (4 u) ] [  Libre (2 u)  ] [ P2 (3 u) ]
Mapa Bits:    1  1  1  1     0         0      1  1  1

Lista:        [P | Inicio:0 | Long:4] ──> [H | Inicio:4 | Long:2] ──> [P | Inicio:6 | Long:3]
```
### A. Mapa de Bits
* La memoria se divide en **unidades de asignación** fijas
* Cada unidad se representa mediante 1 bit : `1` (ocupado), `0` (libre)
* *Compromiso*: Unidades pequeñas generan mapas de bits muy grandes. Unidades grades generan fragmentación interna dentro de la unidad

### B. Listas Enlazadas
* Mantiene una lista ordenada por direcciones con nodos que representan un **Proceso (P)** o un **Hueco (H)**, indicando inicio y longitud

* **Fusión de Huecos:** Al terminar un proceso $T$, el SO verifica a sus vecinos para fusionar bloques libres adyacentes.

| Escenario Vecinos | Acción sobre la Lista Enlazada |
| :--- | :--- |
| **Proceso – $T$ – Proceso** | Se reemplaza el nodo $P$ (proceso) por un nodo $H$ (hueco). |
| **Hueco – $T$ – Proceso** | Se fusionan en un solo nodo $H$ (la lista se reduce en 1 nodo). |
| **Proceso – $T$ – Hueco** | Se fusionan en un solo nodo $H$ (la lista se reduce en 1 nodo). |
| **Hueco – $T$ – Hueco** | Se fusionan los tres nodos en un solo nodo $H$ (la lista se reduce en 2 nodos). |

## 3.2.6 Estrategias de Colocación (Particiones Dinámicas)
Algoritmos para seleccionar el hueco de memoria al asignar espacio a un proceso:

| Algoritmo | Mecanismo de Búsqueda | Ventajas / Comportamiento | Inconvenientes |
| :--- | :--- | :--- | :--- |
| **Primer Ajuste<br>(First Fit)** | Recorre la lista desde el inicio y asigna el primer hueco suficientemente grande. | Extremadamente rápido. Minimiza las búsquedas. | Tiende a acumular pequeños huecos inutilizables al principio de la memoria. |
| **Mejor Ajuste<br>(Best Fit)** | Examina toda la lista y selecciona el hueco más pequeño donde quepa el proceso. | Conserva los huecos grandes intactos para procesos futuros. | Produce el peor desperdicio global: crea multitud de minúsculos huecos inservibles. |
| **Peor Ajuste<br>(Worst Fit)** | Examina toda la lista y selecciona el hueco más grande disponible. | El hueco sobrante tras la asignación suele ser lo bastante grande para otro proceso. | Agota rápidamente los grandes bloques de memoria necesarios para procesos pesados. |

## 3.2.7 Intercambio (Swapping)
Técnica qeu permite aumentar el **grado de multiprogramación** moviendo procesos completos entre la memoria principal y la memoria secundaria (disco)

```cpp
                       ┌──────────────────┐
                       │  MEMORIA RAM     │
                       │                  │
                       │   [Proceso A]    │
                       └────────┬─────────┘
                                │ Swapping Out (Desalojo)
                                ▼
┌──────────────────────────────────────────────────────────┐
│                   DISCO DE INTERCAMBIO                   │
│                       (Swap Space)                       │
└──────────────────────────────────────────────────────────┘
                                ▲
                                │ Swapping In (Carga)
                       ┌────────┴─────────┐
                       │   [Proceso B]    │
                       │  MEMORIA RAM     │
                       └──────────────────┘
```

### EL intercambiador (Swapper)
Módulo del planificador a medio plazo que gestiona la transferencia de procesos
* **Criterios de Elección de Víctima (Swap out)**
1. Estado del proceso: Se prioriza evacuar procesos en estado **Bloqueado** (pasan a Suspendido-Bloqueado)
2. Prioridad y tiempo de residencia: Procesos con bajo nivel de prioridad o que hayan consumido mucho tiempo de CPU
3. Previene la hiperactividad (Thrashing): Un proceso debe permanecer al menos **" egundos** en memoria antes de ser candidato a Swap Out

* **Estrategias de Recuperación (Swap in)**:
    * **Intercambio Fácil**: Existe espacio libre suficiente en RAM para cargar el proceso directamente dese el disco
    * **Intercambio Difícil**: Requiere expulsar a uno o varios procesos de la RAM al disco para liberar el espacio exacto necesitado
