# 3.1. Introducción a la Gestión de Memoria
La memoria principal es una matriz de palabras o bytes, cada uno con su propia dirección física. El SO debe controlar la asignación de este espacio escaso para mantener varios procesos simultáneos

### Tareas Principales del Gestor de Memoria
* **Registro de estado:** Mantener un control de qué zonas están libres y cuáles están ocupadas (y por qué procesos).

* **Intercambio (Swapping):** Mover código y datos entre la memoria principal y el disco (memoria secundaria) cuando no hay espacio suficiente, de forma transparente al usuario.

* **Protección y Aislamiento:** Garantizar que un proceso no pueda leer ni modificar (privacidad y seguridad) la memoria de otro proceso ni la del propio SO.

### Factores de Diseño en la Asignación de Memoria
1. **Asignación contigua:** Particiones Estáticas y Dinámicas

2. **Asignación no contigua:** Paginación, Segmentación y Segmentación Paginada

3. **Mecanismos de traducción de direcciones:** Esenciales para calcular el tiempo efectivo de acceso a memoria y determinar el rendimiento

## 3.2 Conceptos Generales
## 3.2.1. Jerarquía de Memoria
Para equilibrar coste, velocidad y capacidad, la memoria se organiza jerárquicamente. A menor nivel, mayor velocidad y coste, pero menor capacidad

```text
[ Registros CPU ]          ▲ Más rápido / Más caro / Menor capacidad
          │
    [ Caché ] (L1/L2/L3)     │
          │
 [ Memoria Principal ] (RAM) │
          │
[ Memoria Secundaria ] (SSD/HDD) ▼ Más lento / Más barato / Mayor capacidad
```
* **Memoria Caché:** Memoria de muy alta velocidad interpuesta entre la CPU y la RAM. Reduce el tiempo de acceso ejecutando temporalmente allí los bloques de programas/datos más usados

* **Memoria Secundaria (Disco):** Soporte no volátil de gran capacidad y bajo coste usado para almacenamiento permanente e intercambio (swapping)

## 3.3 Gestión de Memoria en Sistemas Monoprogramados
En sistemas con un solo proceso de usuario, la gestión es mínima: la memoria solo se divide entre el SO y dicho proceso

### Formas de Organización
* **SO en RAM baja** y proceso en la parte alta

* **SO en ROM alta** y proceso en RAM baja

* **Híbrido (ej. IBM PC):** Parte del SO en RAM y controladores básicos en ROM (BIOS/UEFI).

### Direccionamiento y Protección
#### Direcciones Absolutas vs. Relativas
* **Absoluta (Física):** Dirección real fija en memoria hardware

* **Relativa (Lógica):** Generada asumiendo que el programa empieza en la dirección 0. Los compiladores usan direcciones relativas al no saber dónde se cargará el programa

**Protección mediante Registro Límite:** En sistemas monousuario/monoprogramados la protección suele ser nula. Sin embargo, se puede usar un **Registro de Límite** en la CPU con la dirección de inicio del SO. Si el proceso de usuario genera una dirección que supera o invade la zona protegida, el hardware lanza una interrupción para abortar el proceso

## 1.4. Gestión de Memoria en Sistemas Multiprogramados
Al residir múltiples procesos simultáneamente, surgen retos como la **reubicación dinámica** (traducir direcciones lógicas a físicas en tiempo de ejecución) y la **protección entre procesos**.

### Resumen de Técnicas de Gestión de Memoria
| Técnica | Descripción | Ventajas / Fortalezas | Inconvenientes / Debilidades |
| :--- | :--- | :--- | :--- |
| **Particiones Estáticas** | La memoria se divide en regiones fijas al generar el sistema. | Sencillo de implementar; muy baja sobrecarga (*overhead*) para el SO. | Fragmentación interna; número máximo de procesos activos fijo. |
| **Particiones Dinámicas** | Las regiones se crean dinámicamente ajustándose al tamaño exacto del proceso. | Sin fragmentación interna; uso más eficiente de la RAM. | Uso ineficiente de la CPU debido a la necesidad de compactar para solucionar la fragmentación externa. |
| **Paginación Simple** | RAM dividida en marcos (*frames*) fijos. Proceso dividido en páginas del mismo tamaño. Carga no contigua. | Sin fragmentación externa. | Pequeña cantidad de fragmentación interna (en la última página). |
| **Segmentación Simple** | Proceso dividido en segmentos lógicos de tamaño variable. Carga no contigua. | Sin fragmentación interna; mejor uso de memoria respecto a particiones dinámicas. | Fragmentación externa. |
| **Memoria Virtual<br>(Paginación)** | Igual que la paginación simple, pero no requiere cargar todas las páginas del proceso en RAM. | Sin fragmentación externa; mayor grado de multiprogramación; espacio de direcciones muy grande. | Sobrecarga por la complejidad en la gestión de memoria (*page faults*, tablas de páginas). |
| **Memoria Virtual<br>(Segmentación)** | Igual que la segmentación simple, pero no requiere cargar todos los segmentos en RAM. | Sin fragmentación interna; alto grado de multiprogramación; soporte nativo para protección y compartición. | Sobrecarga por la complejidad de la gestión. |
