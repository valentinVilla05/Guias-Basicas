# 4.4. Factores en la Selección del Tamaño de Página
No existe un tamaño único óptimo de página. Los tamaños siempre son potencias de dos (desde $512\text{ B}$ hasta $16\text{ MB}$, siendo $4\text{ KB}$ el estándar habitual). La elección responde a un compromiso entre distintas variables del sistema:

| Factor | Tamaño de Página Pequeño | Tamaño de Página Grande |
| :--- | :--- | :--- |
| **Tamaño de la Tabla de Páginas** | **Desfavorable:** Mayor número de páginas; la tabla ocupa demasiado espacio en RAM. | **Favorable:** Menos páginas por proceso; tablas de páginas más reducidas. |
| **Fragmentación Interna** | **Favorable:** Minimiza el espacio desperdiciado en la última página del proceso ($\approx S/2$). | **Desfavorable:** Mayor desperdicio de memoria no ocupada en el último bloque. |
| **Tiempo de E/S en Disco** | **Desfavorable:** Prevalecen los tiempos de búsqueda y latencia del disco frente al tiempo de transferencia. | **Favorable:** Aprovecha mejor la transferencia al amortizar la latencia y la búsqueda. |
| **Ajuste a la Localidad** | **Favorable:** Mayor resolución; permite cargar en RAM únicamente el código necesario. | **Desfavorable:** Carga código/datos no requeridos junto con los datos activos. |
| **Frecuencia de Fallos de Página** | **Desfavorable:** Aumenta el número global de fallos de página y la sobrecarga de gestión. | **Favorable:** Reduce la tasa de fallos de página del sistema. |
|

> Evolución histórica: La tendencia del hardware va hacia páginas de mayor tamaño ($4\text{ KB}$, $2\text{ MB}$, $1\text{ GB}$) debido a que el rendimiento del procesador y la capacidad de la memoria principal han crecido a un ritmo mucho más rápido que la velocidad de lectura/escritura de los discos

## 4.4.1 Estructuras Avanzadas de la Tabla de Páginas
Para traducir la dirección lógica $(\text{Número de Página Virtual}, \text{Desplazamiento})$ a la dirección física $(\text{Número de Marco}, \text{Desplazamiento})$, la tabla de páginas debe residir en memoria principal.

### Problema de Escalabilidad
En espacios de direcciones virtuales extensos, la tabla de páginas estándar por proceso alcanza un tamaño inasumible en memoria física

* **Ejemplo de cálculo (Arquitectura VAX):**
* Memoria virtual por proceso: $2^{31}\text{ bytes} = 2\text{ GB}$.
* Tamaño de página: $2^{9}\text{ bytes} = 512\text{ bytes}$.
* Entradas de la Tabla de Páginas (ETP): $2^{31 - 9} = 2^{22}$ entradas.
* Tamaño por entrada (ETP): $3\text{ bytes}$ ($22\text{ bits}$ de marco + bits de control).
* Tamaño total de la tabla: $2^{22} \times 3\text{ bytes} = 12\text{ MB}$ por cada proceso activo.

#### 1. Tabla de Páginas Jerárquica (Dos Niveles)
Divide la tabla de páginas del usuario en bloques que también son paginados en memoria virtual, manteniendo fija en la memoria física únicamente una tabla raíz (directorio de páginas) que ocupa exactamente una página

```text
DIRECCIÓN VIRTUAL (32 bits)
┌──────────────────────┬──────────────────────┬────────────────────────┐
│ P1: Índice Raíz (10) │ P2: Índice Tabla (10)│ Desplazamiento d (12) │
└──────────────────────┴──────────────────────┴────────────────────────┘
          │                      │                         │
          ▼                      │                         │
  ┌───────────────┐              │                         │
  │  Tabla Raíz   │              │                         │
  │ (Directorio)  │              │                         │
  ├───────────────┤              ▼                         │
  │    ETP N1     ├──────► ┌───────────────┐               │
  └───────────────┘        │ Tabla Usuario │               │
                           ├───────────────┤               │
                           │    ETP N2     ├───────┐       │
                           └───────────────┘       │       │
                                                   ▼       ▼
                                            ┌────────────────────┐
                                            │   Marco Físico + d │
                                            └────────────────────┘
```

* **Mapeo paso a paso (Arquitectura de 32 bits, páginas de $4\text{ KB}$):**
1. **Espacio de direcciones:** $2^{32}\text{ bytes} = 4\text{ GB}$ ($2^{20}\text{ páginas}$)
2. **Tabla de usuario sin paginar:** $2^{20}\text{ entradas} \times 4\text{ bytes/ETP} = 4\text{ MB}$ ($1.024\text{ páginas}$)
3. **Estructura jerárquica:**
    * **10 bits ($P_1$)**: Seleccionan la entrada en el directorio o tabla raíz ($1.024\text{ entradas} = 4\text{ KB}$, $1\text{ página}$)
    * **10 bits ($P_2$):** Seleccionan la entrada en la tabla de páginas de usuario de segundo nivel
    * **12 bits ($d$):** Representan el offset o desplazamiento dentro de la página ($2^{12} = 4\text{ KB}$)

#### 2. Tabla de Páginas Invertida
A diferencia de los esquemas jerárquicos —cuyo tamaño es proporcional al espacio de memoria virtual—, la tabla de páginas invertida escala proporcionalmente a la memoria física del sistema

```text
Dirección Virtual: [ PID | Página Virtual | Desplazamiento ]
                                  │
                                  ▼
                         [ Función Hash ]
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                    TABLA DE PÁGINAS INVERTIDA                   │
├──────────────┬──────────────┬─────────────┬─────────────────────┤
│ ÍNDICE MARCO │  Proceso PID │ Pág. Virtual│ Puntero Encadenado  │
├──────────────┼──────────────┼─────────────┼─────────────────────┤
│   Marco 0    │     PID_A    │    Pág_X    │       NULL          │
│   Marco 1    │     PID_B    │    Pág_Y    │       Index_N       │ ──► Colisión Hash
│     ...      │      ...     │     ...     │         ...         │
└──────────────┴──────────────┴─────────────┴─────────────────────┘
```
* **Estructura del Registro:** Existe exactamente una entrada por cada marco de memoria física real.

* **Mecanismo de búsqueda:** 
1. Se toma la combinación de $(\text{PID}, \text{Página Virtual})$ de la dirección lógica
2. Se aplica una función hash que indexa la tabla invertida.Si ocurren colisiones, se resuelve mediante encadenamiento (overflow chain) comprobando el puntero

* **Campos clave por entrada:**
* **Número de página virtual:** Identificador de la página del proceso
* **PID:** Identificador del proceso propietario
* **Bits de control:** Flags de presencia, modificación, referencia y protección
* **Puntero de cadena:** Enlace a la siguiente entrada en caso de colisión hash.
