# 3.3 Asignación de memoria no Contigua
En la asignación no contigua, el espacio de direcciones de un proceso se divide en bloques que pueden ubicarse en osiciones físicas disperssas dentro de la memoria RAM. Además no es necesario que todos los bloques de proceso resida en la memoria principal al mismo tiempo para su ejecución

## 3.3.1 La Memoria Virtual
Desacopla el espacio de direcciones que utiliza el proceso (Espacio de Direcciones Virtuales, $V$) del espacio de direcciones de la memoria RAM real (Espacio de Direcciones Reales, $R$). Por lo general, $\vert{}V\vert{} \gg \vert{}R\vert{}$, lo que permite ejecutar programas que exceden la capacidad de la memoria física

```text
Espacio Virtual (V)                    Memoria Real (RAM, R)
┌──────────────────┐                   ┌──────────────────┐
│     Bloque 0     │──────────────────►│     Bloque 0     │
├──────────────────┤                   ├──────────────────┤
│     Bloque 1     │────┐              │     Bloque 2     │
├──────────────────┤    │              ├──────────────────┤
│  Bloque 2 (Disco)│    └─────────────►│     Bloque 1     │
└──────────────────┘                   └──────────────────┘
```

### Principio de Localidad (Denning, 1970)
La memoria virtual funciona gracias a que las referencias a memoria de un proceso no son aleatorias, sino altamente estructuradas en tiempo y en espacio

* **Localidad Temporal**: Si una posición de memoria es referenciada, tiende a ser referenciada de nuevo en el futuro cercano (ej: bucles, variables locales)

* **Localicad Espacial**: Si se accede a una posición de memoria, es muy probable que se acceda pronto a posiciones adyacentes (ej: ejecución secuencial de código, recorrido de vectores)

## 3.3.2 Esquema General de Traducción
La dirección virtual se expresa como un par bidimensional $v = (b, d)$:
* $b$: número de bloque
* $d$: desplazamiento (offset) dentro del bloque

```text
Dirección Virtual v = (b, d)
 ┌─────────────────┬─────────────────┐
 │   Bloque (b)    │ Desplazamiento(d)│
 └────────┬────────┴────────┬────────┘
          │                 │
          ▼                 │
 ┌──────────────────┐       │
 │ Tabla de Bloques │       │
 ├──────────────────┤       │
 │ b  │ Base (b')   │       │
 └────┼─────────────┘       │
      │                     │
      └──────────┐  ┌───────┘
                 ▼  ▼
     Dirección Real r = b' + d
```

### Proceso de Traducción por Hardware
1. La CPU genera una dirección virtual $v = (b, d)$.
2. Se consulta la Tabla de Correspondencia de Bloques del proceso en curso (su dirección base se almacena en el registro hardware correspondiente durante el cambio de contexto)
3. Se obtiene la dirección física de inicio del bloque ($b'$)
4. La dirección física final se calcula como:
$$r = b' + d$$

### Bit de Presencia y Fallo de Bloque
Cada entrada de la tabla incluye un **Bit de Presencia**:
* `1` (Presente): El bloque está cargado en la memoria RAM y la traducción procede por hardware
* `0` (No Presente): El bloque está en el disco. El hardware genera una interrupción/excepción (Fallo de Bloque/Página), pasando el control al SO para que:
    1. Inicie la transferencia de E/S del bloque desde el disco a la RAM
    2. Bloquee el proceso solicitante
    3. Actualice la tabla de correspondencia cuando se complete la lectura

## 3.3.3 Paginación
División del espacio de direcciones del proceso en bloques de **tamaño fijo** llamados **Páginas**, y la memoria física en bloques del mismo tamaño llamados **Marcos de Página** (frames)

```text
Dirección Lógica:  [ Número de Página (p) | Desplazamiento (d) ]
                               │                        │
                               ▼                        │
                         Tabla de Páginas               │
                         ┌───┬─────────┐                │
                         │ p │ Marco f │                │
                         └───┴────┬────┘                │
                                  │                     │
                                  ▼                     ▼
Dirección Física:  [   Número de Marco (f)   | Desplazamiento (d) ]
```

### Dirección Lógica a Física
Dado que el tamaño de página $S = 2^n$ bytes es una potencia de 2, la división entre el número de página ($p$) y el desplazamiento ($d$) se realiza directamente por división de bits:
$$p = \lfloor \text{Dirección Virtual} / S \rfloor \quad \mid \quad d = \text{Dirección Virtual} \pmod S$$
La dirección física resultante se forma concatenando el marco $f$ obtenido con el desplazamiento $d$:
$$\text{Dirección Física} = (f \times S) + d$$

### Rendimiento Hardware: TLB (Translation Lookaside Buffer)
Para evitar realizar dos accesos a RAM por cada referencia a memoria (uno a la Tabla de Páginas y otro al dato), se utiliza una memoria caché asociativa súper rápida denominada **TLB**

```text
                        ┌──────────────────┐
                        │ CPU genera (p,d) │
                        └────────┬─────────┘
                                 │
                         ┌───────┴───────┐
                         │ ¿Está p en TLB?│
                         └───────┬───────┘
                    SÍ (Acierto) │ │ NO (Fallo)
          ┌──────────────────────┘ └──────────────────────┐
          ▼                                               ▼
  Obtener marco f                             Consultar Tabla de Páginas en RAM
  en 20 ns                                    (requiere 100 ns extras)
```

* **Tiempo de Acceso Efectivo (EAT)**:
$$\text{EAT} = (\text{Tasa de Acierto}) \times (\text{Tiempo TLB} + \text{Tiempo RAM}) + (1 - \text{Tasa de Acierto}) \times (\text{Tiempo TLB} + 2 \times \text{Tiempo RAM})$$

Ejemplo con $80\%$ aciertos, $20\text{ ns}$ TLB y $100\text{ ns}$ RAM:
$$\text{EAT} = 0.80 \times (20 + 100) + 0.20 \times (20 + 100 + 100) = 0.80 \times 120 + 0.20 \times 220 = 140\text{ ns}$$

### Protección y Código Reentrante
* **Bits de Protección**: Añadidos en la Tabla de Páginas para indicar permisos (`Lectura, Escritura, Ejecución)

Páginas Compartidas: Código **reentrante** (no automodificable) permite que múltiples procesos apunten a los mismos marcos físicos de código (p. ej., bibliotecas del sistema, editores), duplicando únicamente sus páginas de datos individuales

## 3.3.4 Segmentación
División del espacio de memoria según la **visión lógica del programador**. Un programa se compone de **Segmentos de tamaño variable** (funciones, pila, datos globales, etc.)

```text
Dirección Lógica:  [ Número de Segmento (s) | Desplazamiento (d) ]
                               │                         │
                               ▼                         │
                         Tabla de Segmentos              │
                         ┌───┬────────┬────────┐         │
                         │ s │ Límite │ Base   │         │
                         └───┴───┬────┴───┬────┘         │
                                 │        │              │
                                 │        ▼              │
                         ¿d < Límite? ───(+)─────────────┘
                              │           │
                          NO  │           ▼
                      Excepción      Dirección Física Real
```

### Esquema de Traducción y Verificación Hardware
Una dirección lógica consta de $(s, d)$:
1. Se consulta el número de segmento $s$ en la **Tabla de Segmentos**.
2. **Chequeo de Protección:** Se verifica si $d < \text{Límite}$.
    * Si $d \ge \text{Límite} \longrightarrow$ Genera una excepción por violación de memoria (Segmentation Fault).
3. Si el desplazamiento es válido:
    $$\text{Dirección Física} = \text{Base del Segmento} + d$$

### Comparativa: Paginación vs. Segmentación
| Criterio | Paginación | Segmentación |
| :--- | :--- | :--- |
| **Visión del espacio** | Hardware / Sistema Operativo (bloques fijos). | Programador (módulos lógicos variables). |
| **Tamaño de bloque** | Fijo (potencia de 2). | Variable según necesidades del módulo. |
| **Direccionamiento** | Unidimensional (el HW extrae $p$ y $d$). | Bidimensional explícito: $(s, d)$. |
| **Fragmentación** | Fragmentación Interna (en la última página de cada proceso). | Fragmentación Externa (huecos variables entre segmentos en la RAM). |
| **Ventaja principal** | Fácil gestión de marcos; sin fragmentación externa. | Facilidad para compartir y proteger módulos de forma semántica. |
|

## 3.3.5 Segmentación Paginada
Combina las ventajas de la segmentación (visión lógica del usuario, protección y compartición modular) con las de la paginación (eliminación de la fragmentación externa y asignación sencilla de marcos)
```text
Dirección Lógica: [ Número de Segmento (s) | Número de Página (p) | Desplazamiento (d) ]
                               │                         │                    │
                               ▼                         │                    │
                      Tabla de Segmentos                 │                    │
                      ┌───┬───────────────────┐          │                    │
                      │ s │ Dir. Tabla Págs.  │          │                    │
                      └───┴─────────┬─────────┘          │                    │
                                    │                    │                    │
                                    ▼                    ▼                    │
                            Tabla de Páginas del Segmento                     │
                            ┌───┬─────────┐                                   │
                            │ p │ Marco f │                                   │
                            └───┴────┬────┘                                   │
                                     │                                        │
                                     ▼                                        ▼
    Dirección Física:       [ Número de Marco (f)          | Desplazamiento (d) ]
```

### Esquema de Traducción de Direcciones
La dirección lógica se compone de una tripleta $v = (s, p, d)$:
1. **El Número de Segmento ($s$)** indexa la **Tabla de Segmentos** del proceso. La entrada no contiene la dirección base del segmento, sino la dirección física de la Tabla de Páginas correspondiente a dicho segmento.

2. El **Número de Página ($p$)** indexa la Tabla de Páginas de ese segmento específico para obtener el **Número de Marco ($f$)** en la memoria RAM

3. El **Desplazamiento ($d$)** se combina directamente con el Marco ($f$) para formar la dirección física final

### Caso Prácttico Histórico: Sistema Multics (Ge 645)
* **Dirección Lógica (34 bits):** $18\text{ bits}$ de segmento ($262.144$ segmentos) y $16\text{ bits}$ de desplazamiento

* **División del Desplazamiento:** Los $16\text{ bits}$ se fragmentan en $6\text{ bits}$ para el número de página y $10\text{ bits}$ para el desplazamiento dentro de la página ($1\text{ KiB}$ por página)

* **Paginación Jerárquica de la Tabla de Segmentos:** Dado que $18\text{ bits}$ generan una Tabla de Segmentos gigante, Multics implementa **paginación sobre la propia Tabla de Segmentos** para evitar requerir memoria contigua para las tablas del sistema

### Balance de Memoria en Segmentación Paginada
* **Fragmentación Externa:** $\mathbf{0}$ (eliminada por completo gracias a la paginación)

* **Fragmentación Interna:** Promedio de media página por segmento (en la última página de cada segmento del proceso)

* **Sobrecarga de Tablas:** Se incrementa el uso de memoria, ya que cada segmento requiere su propia tabla de páginas


## 3.3.6 Memoria Comprimida
Técnica moderna de gestión de memoria que actúa como alternativa y complemento a la memoria virtual convencional en disco (swapping). Su objetivo principal es evitar las lentas operaciones de E/S en almacenamiento secundario

```text
[Proceso Inactivo / Bloqueado] 
                │
                ▼
  ┌──────────────────────────┐
  │ Algoritmo de Compresión  │ (Ej: WKdm / zRAM)
  └─────────────┬────────────┘
                │
                ▼
  ┌──────────────────────────┐
  │ RAM: RAM-Zip / Paginación│ ◄── Ocupa ~50% menos espacio en la memoria
  └──────────────────────────┘
```

### Funcionamiento
En lugar de volcar (swap out) las páginas de procesos inactivos o bloqueados al disco duro o SSD, el sistema operativo las comprime directamente en la propia memoria RAM

* Si un nuevo proceso necesita espacio, las páginas comprimidas liberan suficiente memoria RAM sin necesidad de acceder a la memoria secundaria

* Si eventualmente se requiere un volcado a disco, la memoria comprimida sigue ofreciendo ventajas: al transferir páginas ya comprimidas, se reduce a la mitad el volumen de datos a transferir por el bus de E/S

### Factores Hardware Determinantes
Aunque el concepto no es nuevo, su adopción práctica actual ha sido impulsada por:

1. **Procesadores Multinúcleo:** Permiten paralelizar las tareas de compresión y descompresión en hilos secundarios sin congelar el hilo principal

2. **Algoritmos de Compresión Ultrarrápidos:** Algoritmos como WKdm o zRAM ofrecen tasas de compresión del $50\%$ con un impacto de procesamiento mínimo

### Ventajas Principales
| Parámetro | Memoria Virtual Tradicional (Disco/SSD) | Memoria Comprimida (RAM) |
| :--- | :--- | :--- |
| **Latencia / Tiempo de respuesta** | Lenta (milisegundos por E/S en disco). | Ultrarrápida (microsegundos por compresión en CPU). |
| **Eficiencia energética** | Elevada (el acceso al disco consume mucha energía). | Mínima (ideal para dispositivos portátiles y móviles). |
| **Paralelismo** | Limitado por el ancho de banda del canal E/S. | Alto (aprovecha la arquitectura multinúcleo para procesar simultáneamente). |
|

### Implementaciones Reales
* **Linux / Ubuntu:** Implementado mediante el módulo ´zram´ (´zram-config´), que crea un dispositivo de bloques comprimido en la memoria RAM que actúa como área de intercambio

* **macOS:** Introducido desde OS X Mavericks utilizando el algoritmo WKdm
