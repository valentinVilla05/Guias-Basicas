# 2 . Estructuras de los Sistemas Operativos
Estudia la organización interna del código del SO y cómo sus componentes se conectan para formar el **kernel** (núcleo)

## 2.1 Sistemas Monolíticos / Estructura Simple
* **Concepto**: Colección de procedimientos donde **cualquiera puede llamar a cualquier otro** si lo necesita. Ocultación de información prácticamente nula ( todo es visible para todos)

* **Mecanismo de Llamada**:
1. Los parámetros se colocan en registros/pila y se ejecuta una instrucción especial **trap** (llamada al núcleo / supervisor)
2. La máquina cambia de **modo usuario -> modo núcleo**
3. El SO examina los parámetros, consulta una tabla de punteros a procedimientos y ejecuta el servicio correspondiente
4. El control regresa al problema de usuario

* **Estructura básica de 3 capas**:
1. Programas principales (invocan servicios)
2. Procedimientos de servicio (realizan llamadas al sistema)
3. Procedimientos de utilidad (auxiliares, ej : buscar datos de usuario)

* Ejemplos históricos:
* **MS-DOS:** Sin separación clara de interfaces/niveles . Las aplicaciones acceden directamente al hardware. AL carecer de modo dual por hardware (procesamiento Intel 8088)
* **Unix Original**: todo lo situado entre las llamadas al sistema y el hardware es el kernel

## 2.2 Estructura en Niveles (Capas)
* **Concepto**: El sistema se modulariza en una jerarquía en capas: desde el Nivel 0 (**hardware**) hasta el **Nivel N (Interfaz de usuario)**. cada capa $i$ utiliza exclusivamente los servicios e la capa inferior $i-1$ y ofrece la intefrfaz a la superior $i+1$

* **Inconvenientes**
* Dificultad para definir adecuadamente que funcionalidad va en cada nivel
* **Ineficiencia**: Añade una sobrecarga de trabajo (overhead) a las llamadas al sistema por tener que atravesar múltiples capas

## 2.3 Modelo Cliente-Servidor / Microkernel (Micronúcleo)
* **Concepto**: Se reduce el núcleo al mínimo posible (microkernel). La mayoría de las funciones tradicionales del SO se ejecutan como procesos en **modo usuario**
* **Funcionamiento**: Un proceso cliente envia un mensaje a un proceso servidor. El micronucleo **solo gestiona la comunicación (paso de mensajes)** entre ellos

```cpp
+-------------------------------------------------------------------+
  |                           MODO USUARIO                            |
  |                                                                   |
  |   +------------------+                    +------------------+    |
  |   | Proceso CLIENTE  |                    | Proceso SERVIDOR |    |
  |   |   (ej. App)      |                    | (ej. Archivos)   |    |
  |   +--------+---------+                    +--------^---------+    |
  |            |                                       |              |
  |  1. Envía  |                                       | 3. Entrega   |
  |     mensaje|                                       |    mensaje   |
  +------------|---------------------------------------|--------------+
  ======================= LLAMADA AL SISTEMA ==========================
  +------------|---------------------------------------|--------------+
  |            v                                       |              |
  |   +------------------------------------------------+----------+   |
  |   |                       MICRONÚCLEO                         |   |
  |   |           2. Conmuta y gestiona el mensaje            |   |
  |   +-----------------------------------------------------------+   |
  |                                                                   |
  |                            MODO NÚCLEO                            |
  +-------------------------------------------------------------------+
```
* **Ventajas:**
    * **tolerancia a fallos**: Si un servidor (ej: gestor de archivos) falla, no colapsa todo el sistema porq rueda en modo usuario
    * **Sistemas distribuidos**: Elcliente envía solicitudes por mensaje sin importar si el servidor está en la misma máquina o en una remota a través de red

* **Desafío y soluciones** para acceso hardware:
    1. Ejecutar algunos servidores críticos (ej drivers de E/S) en modo núcleo
    2. Mantener en el núcleo solo el **mecanismo** (ej : copiar mensajes a registros del controlador) y dejar la **política** en espacio de usuario
* **Principio de Mecanismos vs Políticas**

* **Mecanismos**: Cómo se hace algo (ej: algoritmo pa cambiar la prioridad a un proceso). Reside en el kernel
* **Políticas**: Qué se hace (ej: decidir si se prioriza la E/S o la CPU). Reside en el eespacio de usuario

## 2.4 Módulos (Carga dinámica)
* **Concepto**: Uso de programación orientada a objetos para crear un kernel modular y flexible
* **Funcionamiento**: El kernel contiene los componentes esenciales y **enlaza dinámicamente** otros servicios/módulos en tiempo de ejecución o arranque

* **Comparativa**:
* Como la Estructura en Niveles: Interfaecs bien definidas
* Como el Microkernel: El módulo principal solo tiene lo esencial y sabe como comunicarse como el resto
* **Más eficiente que un Microkernel**: Los módulos no necesitan un mecanismo de paso de mensajes para comunicarse

> Ejemplos: Implementaciones modernas de UNIX (Solaris, Linux, macOS)

## 2.5. Máquinas Virtuales (Virtualización)
* **Concepto**: Abstrae el hardware físico para suministrar copias idénticas llamadas "maquinas abstractas". Multiplexa los recursos físicos (CPU, memoria, red) entre varias **VMs** (**Guests**)

* **Ventajas y Desventajas**
    * **Ventaja**: Aislamiento total, seguridad y capacidad de eejecutar varios SOs simultáneos
    * **Desventaja**: Degradación del rendimiento por la sobrecarga de la simulación
* **El HiperVisor / VMM (Virtual Machine Monitor)**: Capa del sofware que gestiona la traducción de recursos entre el hardware anfitrión (**Host**) y las máquinas huéspedes (**Guests**)

| Tipo | Dominación | Ejecución / Dependencia | Rendimiento y USo | Ejemplos |
| -- | -- | -- | -- | -- |
| **Tipo 1** | Nativo / Bare-Metal | Directamente sobre el hardware físico (sin SO) | **Mayor rendimiento y eficiencia**. Utilizado en centros de datos/servidores |  VMware ESXi, Microsoft Hyper-V.. | 
| **Tipo 2** | Alojado / Hosted | Sobre un SO anfitrión existente (depende de él para los recursos) | **Mayor Latencia**. Un fallo en el SO host afecta a todas las VMs . Usado en entorno cliente / desarrollo | VirtualBox, VMware, Workstation , Parallels |
