# Examen 2022

1. **[V] De las dos definiciones siguientes, el dato de $q$ se establece en la pila y el de $p$ en el heap:**

```cpp
void lacosa () {
    int q = 3;
    int *p = new int; *p = 5;
    ...
}
```

> **Explicación**: Las variables locales directas (int q) se almacenan en la memoria pila (stack), mientras que la memoria reservada dinámicamente con new (new int) se ubica en la memoria libre (heap)

2. **[F] Si no se libera la memoria de $p$ en la función anterior lacosa(), entonces se produce un desbordamiento o overflow**

> **Explicación**: Si no se libera la memoria dinámicamente reservada se produce una fuga de memoria (memory leak), no un desbordamiento (overflow)

3. **[F] Si la clase $A$ tiene una composición a muchos con la clase $B$ y con la clase $C$, comportándose ambas de forma dinámica, y la clase $C$ tiene una asociación a muchos con la clase $B$, entonces no es buena idea usar un vector de STL para la relación entre $A$ y $B$.**

> **Explicación**: Un `std::vector` de punteros o de objetos es una de las estructuras de la STL más adecuadas y estándar para gestionar relaciones dinámicas de uno-a-mucho

4. **[F] El constructor copia de la clase ListaEnlazada<T> no necesita destructor si se usa en una asociación.**

> **Explicación**: Toda clase que maneje memoria dinámica internamente (como una lista enlazada) **siempre** necesita un destructor adecuado para liberar sus nodos y evitar fugas de memoria

5. **[F] Una matriz dispersa y un grafo implementado mediante listas invertidas tienen la misma definición usando STL**

> **Explicación**: Una matriz dispersa suele representarse mediante listas de adyacencia/nodos o mapas de pares de coordenadas, mientras que un grafo usa mapas de listas de adyacencia directa, no "listas invertidas"

6. **[V] Aunque insertar/borrar un dato por el final en un `deque<T>` y en un `vector<T>` se considera $O(1)$ es mejor usar un vector<T> para estos casos.**

> **Explicación**: 
`vector` almacena los datos en un bloque contiguo de memoria, ofreciendo mejor localidad de caché y menor sobrecoste de gestión por nodo que `deque` 

7. **[F] El orden de un árbol representa el número de hijos máximo que tiene cada nodo, menos en el árbol B que siempre debe tener ese número de hijos**

> **Explicación**: En un árbol B, el orden especifica el número máximo de hijos posibles por nodo, pero los nodos no están obligados a tener siempre el máximo (tienen un límite inferior y superior de claves/hijos) 

8. **[F] Ocurre que al intentar insertar los datos $v$ y $w$ en una tabla hash cerrada ocurre que $h(v) == h(w)$, por lo que ambos datos podrían realizar el mismo recorrido para insertarse. Esto se llama agrupamiento primario**

> **Explicación**: Cuando dos claves distintas tienen el mismo valor hash original ($h(v) == h(w)$) se denomina agrupamiento secundario. El primario ocurre cuando coinciden las secuencias de exploración de claves con hash distinto.   

9. **[V] Si se utiliza un fichero de datos que mantiene una pila de borrados, la reutilización de una posición de dicho fichero para insertar un nuevo dato se hace con solo tres accesos.**

> **Explicación**: Basta con leer la cabecera del fichero (obtener la cima de la pila de libres), leer/actualizar el puntero del bloque recuperado y escribir el nuevo registro en dicha posición

10. **[V] Si esta sentencia es válida:**

```cpp
int nuevoValor = 7;
it=mieedd.find(clave);
(*it).second[i] = &nuevoValor;
```

**Entonces mieedd puede tener esta definición:**
```cpp
map <int, vector<int*> >mieedd;
```

> **Explicación**: (*it).second accede al valor del mapa (un vector<int*>), [i] accede a la posición $i$ de dicho vector, y &nuevoValor le asigna la dirección de memoria de un int. Los tipos coinciden perfectamente
