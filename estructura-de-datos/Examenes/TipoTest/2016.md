# Tipo Test 2016

**1. [V]** La siguiente definición de vector estático necesita de constructor copia y operador de asignación:

```cpp
template<typename T> class MiVect{
    int tama;
    T *v;
public:
    MiVect(int n){ v=new T[tama=n]; }
    ...
};
```

> **Explicación**: La clase gestiona memoria dinámica mediante un puntero (`T *v`). Siguiendo la regla de los tres, si hay gestión explícita de memoria dinámica con new, se deben definir el constructor de copia y el operador de asignación para evitar que al copiar objetos se dupliquen o liberen mal los punteros (copia superficial)

**2. [F]** La misma clase anterior debe definir así el operador corchete [] para que funcione correctamente (se obvian las comprobaciones de rango)

```cpp
T operator[] (unsigned i) { return v[i]; }
```

> **Explicación**: El operador [] debe devolver una referencia (T& operator[]) para permitir tanto la lectura como la modificación de los elementos del vector (v[i] = valor)

**3. [F]** Si se ha instanciado en la clase Biblioteca a MiVect para implementar una relación de asociación con la clase Libro como:

```cpp
MiVect<Libro*> estante;
```

Entonces el destructor de Biblioteca debe entonces eliminar estante ejecutando:

```cpp
delete[] estante;
```

**Explicación**: En una relación de asociación, la clase principal no es dueña del ciclo de vida de los objetos asociados; además, estante no es un puntero (`MiVect<Libro*>*`), por lo que el uso de delete[] es incorrecto en sintaxis y en diseño de clases

**4. [F]** Esta sería una posible instrucción dentro de la función que elimina el nodo apuntado por el puntero p de una lista doblemente enlazada:

```cpp
p->sig->ant = p->ant;
```

> **Explicación**: Aunque reengancha el puntero ant del nodo siguiente (`p->sig->ant = p->ant`), la instrucción se queda a medias: no elimina el nodo p de la memoria (`delete p;`) ni actualiza el puntero sig del nodo anterior (`p->ant->sig = p->sig;`)

**5. [ V ]** Un vector de listas es un contenedor válido en términos de eficiencia para implementar una cola con prioridad y un grafo aunque no tanto para una matriz dispersa

> **Explicación**: Un vector de listas es la estructura estándar para las listas de adyacencia de un grafo y para listas de prioridad por niveles de enteros pequeños, pero para matrices dispersas bidimensionales resulta ineficiente en memoria y acceso frente a esquemas comprimidos (CSR/CSC) o listas cruzadas

**6. [ F ]** En un árbol AVL, tanto el borrado como la inserción requieren la localización de algún nodo hoja durante el proceso

> **Explicación**: En la inserción sí se localiza una posición hoja donde insertar, pero en el borrado, si se elimina un nodo interno con dos hijos, este se reemplaza por su inorden sucesor o antecesor, lo que no exige descender obligatoriamente hasta un nodo hoja para borrar.

**7. [ V ]** La unión de dos conjuntos disjuntos de tamaños $n$ y $m$ puede llevarse a cabo mediante una operación en $O(1)$

> **Explicación**: Usando estructuras de datos para conjuntos disjuntos (Disjoint-Set / Union-Find), la operación de unión mediante punteros a la raíz (unión por rango/tamaño) se realiza en tiempo constante $O(1)$ sin importar los tamaños $n$ y $m$

**8. [ V ]** Un árbol B de orden cinco que está indexando 500 datos puede tener altura 3 (4 niveles)

> **Explicación**: Un árbol B de orden 5 tiene al menos 2 claves por nodo interno ($\lceil 5/2 \rceil - 1$). La capacidad con 4 niveles ($h=3$) bajo esa ocupación mínima permite albergar holgadamente 500 datos

**9. [ F ]** Para evitar tanto agrupamientos primarios como secundarios a la hora de hacer hashing es preferible utilizar dispersión cuadrática que dispersión doble

> **Explicación**: La dispersión cuadrática elimina el agrupamiento primario pero sufre de agrupamiento secundario (claves con el mismo hash generan idéntica secuencia). La dispersión doble utiliza una segunda función hash que evita ambos tipos de agrupamiento

**10. [ ]** Estas dos definiciones son válidas para almacenar eficientemente las reservas de un hotel por fecha de emisión

```cpp
map<Fecha, list<Reserva>>
multimap<Fecha, Reserva>
```

> **Explicación**: Ambas estructuras de la STL permiten asociar múltiples reservas a una misma fecha: `map<Fecha, list<Reserva>>` agrupa manualmente las reservas en listas por clave, mientras que multimap<Fecha, Reserva> permite directamente claves duplicadas
